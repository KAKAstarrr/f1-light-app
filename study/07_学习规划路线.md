### 核心学习点

**缓存设计思维**:
```
数据请求 → 检查缓存 → 命中? → 返回
                        ↓ 未命中
                   调用 API/FastF1
                        ↓
                   保存缓存
                        ↓
                     返回
```

**为什么用三级而不是一级？**
- Level 1（Ergast JSON）：数据量小，永久有效，不会变
- Level 2（FastF1 .ff1pkl）：官方格式，数据量大，需要它来避免重复下载
- Level 3（结果 JSON）：处理后的数据，过期可能需重新计算

- [ ] 缓存命中时响应 < 200ms
- [ ] 异常分站返回 500 而非崩溃
- [ ] 代码有分层：`main.py`（路由）+ `data_source.py`（数据源）

### 前端选型说明

> ⚠️ **为什么选 Vue 3 而不是 React？**
> React 对新手有较高门槛：JSX 语法心智负担、Hooks 闭包陷阱、useEffect 依赖数组、状态管理选型困难。Vue 3 的模板语法接近写 HTML，响应式自动追踪，中文文档由尤雨溪亲自维护，**对新手友好 3-5 倍**。国内招聘市场 Vue 占比也很高，简历价值不打折。

### 核心学习点

**多通道遥测对比的实现思路**:
```
用户选择 2-3 个车手 + 选择通道（Speed/Throttle/Brake/RPM/nGear/DRS）
    ↓
API 返回: 每车手每通道的 [距离, 值] 数组
    ↓
ECharts 渲染: X轴=距离, Y轴=值, 多系列叠加
    ↓
交互: 悬停读数 / 通道切换 / 车手增删
```

**赛道分段着色的实现思路**:
```
1. FastF1 get_circuit_info() 获取赛道坐标
2. 对每个 mini-sector 计算最快车手
3. 赋色: Purple=全场最快, Green=个人最快, Yellow=慢于个人最佳
4. 前端: Canvas 绘制迷你扇区 + Leaflet 地图底色
```

### 时间分配（假设每天 2-3 小时）

```

理论学习: 25%  （看教程、读官方文档、理解原理）
复盘总结: 15%  （写笔记、记录踩坑、写 README）
```

### 每周节奏

| 星期 | 重点 |
|------|------|
| 周一-周二 | 理论学习 + 小练习 |
| 周三-周五 | 项目编码 |
| 周六 | 集中攻坚难点 |
| 周日 | 复盘 + 文档 + Git commit |

### 避坑指南

1. **不要一上来就学所有技术** — 按阶段来，需要什么学什么
2. **不要追求完美** — 每个阶段先做 MVP，能跑就行，后面再优化
3. **前端从 Streamlit 开始** — 纯 Python，1 天出成果，建立信心后再学 Vue 3
4. **新手选 Vue 3，不选 React** — Vue 3 中文文档更好、模板语法更直觉、3 天上手 vs React 的 2-3 周
5. **善用 AI 辅助编程** — 但不依赖，要能解释每一行代码
6. **记录踩坑** — 每个 Bug 都是一次学习，别忘了写下来
7. **每阶段都产出可展示成果** — 即使卡在阶段 3，阶段 1+2 也是完整项目
