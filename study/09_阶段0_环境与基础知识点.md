## 1. FastAPI 路由与参数

### 概念
FastAPI 用装饰器注册路由，自动生成 OpenAPI 文档。参数分三种：

| 参数类型 | 写法 | 位置 | 示例 |
|---------|------|------|------|
| 路径参数 | `{param}` | URL 路径 | `/api/season/{year}` |
| 查询参数 | `param=default` | URL ? 后面 | `?session_type=R` |
| 请求体 | Pydantic Model | JSON Body | `POST /api/fantasy/team` |

```python
from fastapi import FastAPI

app = FastAPI(title="F1赛车数据后端服务", version="0.1.0")

# 路径参数 + 查询参数混合
@app.get("/api/fastf1/{year}/{round}/fast-lap")
def get_fastf1_fastest_lap(year: int, round: int, session_type: str = 'R'):
    return fetch_fastf1_fastest_lap(year, round, session_type)
```

### 本项目代码（main.py）
```python
@app.get("/api/current-season", summary="获取当前赛季赛历")
def get_current_season():
    return fetch_ergast_current_season()

@app.get("/api/race-result/{year}/{round_num}", summary="获取赛道比赛结果")
def get_race_result(year: int, round_num: int):
    return fetch_ergast_race_result(year, round_num)
```

### 面试问答
**Q: FastAPI 和 Flask 的区别？**
> FastAPI 基于 ASGI（异步），原生支持 async/await；自带 Pydantic 类型校验和 OpenAPI 文档生成；性能比 Flask 快 2-3 倍。Flask 是 WSGI（同步），需第三方扩展做异步、校验、文档。

**Q: 路径参数和查询参数什么时候用？**
> 路径参数标识资源（`/api/season/2025` → 2025 赛季），查询参数做筛选/可选配置（`?session_type=R`）。规则：如果去掉这个参数资源就不存在，用路径参数；如果去掉只是返回不同视图，用查询参数。

**Q: `--reload` 原理？**
> uvicorn 的 `--reload` 用 watchfiles 监听 `.py` 文件变化，检测到修改后重启 worker 进程。开发用，生产环境不开（开销大且有竞态风险）。

## 2. FastAPI 中间件（CORS）

### 概念
CORS（Cross-Origin Resource Sharing）是浏览器安全策略：前端 `localhost:5173` 请求后端 `localhost:8000` 属于跨域，浏览器会先发 OPTIONS 预检请求，后端必须返回正确的 CORS 头才放行。

```
浏览器(5173) --OPTIONS预检--> 后端(8000)
             <--Access-Control-Allow-Origin--
浏览器(5173) --GET实际请求--> 后端(8000)
             <--数据+CORS头--
```

### 本项目代码（main.py）
```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173", "http://127.0.0.1:5173"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

### 面试问答
**Q: CORS 是前端还是后端的问题？**
> 本质是后端问题。CORS 是浏览器行为（不是 HTTP 协议的一部分），浏览器发现跨域后向后端要"许可"。后端不返回 CORS 头，浏览器就拦截响应。用 Postman/curl 不受 CORS 限制（因为不是浏览器）。

**Q: `allow_origins=["*"]` 有什么风险？**
> 生产环境不应设为 `*`（允许任意域名访问），否则任何网站都能调你的 API。应白名单列出可信域名。`allow_credentials=True` 时不能和 `*` 同时用（浏览器会拒绝）。

**Q: 预检请求（OPTIONS）什么时候发？**
> 非简单请求（如 Content-Type: application/json、自定义 Header、PUT/DELETE 方法）会触发预检。简单请求（GET/POST + text/plain）不预检，直接发实际请求。

## 3. Ergast API 数据结构

### 概念
Ergast 是免费的 F1 历史数据库 REST API，提供 1950 年至今的赛程、成绩、排位、积分榜数据。原域名 ergast.com 已停用，项目使用 jolpica 镜像。

```
https://api.jolpi.ca/ergast/f1/
├── current.json                    → 当前赛季赛程
├── {year}.json                     → 历史赛季赛程
├── {year}/{round}.json             → 分站比赛结果
├── current/drivers.json            → 当前赛季车手
├── current/driverstandings.json    → 当前车手积分榜
├── current/constructorstandings.json → 当前车队积分榜
├── {year}/{round}/qualifying.json  → 排位赛结果
└── circuits.json                   → 全部赛道
```

### 嵌套结构（关键！）
```json
{
  "MRData": {
    "RaceTable": {           ← data_source.py 解包到这层
      "Races": [
        {
          "raceName": "Australian Grand Prix",
          "Circuit": {"circuitName": "...", "Location": {"country": "Australia"}},
          "Results": [         ← 分站结果才有
            {"position": "1", "Driver": {"code": "NOR"}, "Constructor": {"name": "McLaren"}}
          ]
        }
      ]
    }
  }
}
```

### 本项目代码（data_source.py —— 解包 MRData）
```python
def _fetch_ergast_data(endpoint: str, cache_key: str, table_name: str):
    raw = resp.json()
    result = raw["MRData"][table_name]   # 解包：去掉外层 MRData
    save_to_cache(cache_key, result)
    return result
```

### 面试问答
**Q: 为什么要解包 MRData？**
> Ergast 返回的数据套了 `MRData → RaceTable → Races` 三层。后端解包到 `RaceTable` 层返回，前端直接用 `data.Races` 即可，不用写 `data.MRData.RaceTable.Races`。减少前端嵌套取值出错。

**Q: Ergast 限流策略是什么？怎么应对？**
> Ergast 限流 200 req/h（无 key）或 5000 req/h（有 key）。本项目用永久 JSON 缓存：首次请求写文件，后续直接读缓存不再请求 API，限流问题完全消除。

## 4. FastF1 核心对象模型

### 概念
FastF1 是 Python 库（非 API），直接从 F1 官方计时接口下载数据，缓存为本地 `.ff1pkl` 文件。

```
fastf1.get_session(year, round, session_type)  → Session 对象
    └── session.load(laps, telemetry, weather, messages)  → 加载数据
            ├── session.laps        → DataFrame（每圈一行）
            ├── session.weather_data → DataFrame（天气）
            └── session.car_data    → DataFrame（遥测，50-100MB）
```

### laps 表关键列

| 列名 | 类型 | 说明 |
|------|------|------|
| `Driver` | str | 车手代码（如 "NOR"） |
| `LapNumber` | int | 圈次 |
| `LapTime` | timedelta64[ns] | **不能直接 JSON 序列化！** |
| `Stint` | int | stint 编号（第几段轮胎） |
| `Compound` | str | 轮胎配方（SOFT/MEDIUM/HARD/INTERMEDIATE/WET） |
| `TyreLife` | int | 轮胎已跑圈数 |
| `FreshTyre` | bool | 是否新胎 |
| `Team` | str | 车队名 |
| `PitInTime` | timedelta64 | 进站时间（无则 NaT） |

### 本项目代码（data_source.py）
```python
import fastf1

FASTF1_HTTP_CACHE = os.path.join(os.path.dirname(__file__), "../cache/fastf1_cache")
fastf1.Cache.enable_cache(FASTF1_HTTP_CACHE)
fastf1.set_log_level("Warning")

session = fastf1.get_session(year, round_num, session_type)
session.load(laps=True, telemetry=False, weather=False, messages=False)
laps = session.laps  # pandas DataFrame
```

### 面试问答
**Q: `session.load()` 的参数为什么只开 `laps=True`？**
> `telemetry=True` 会下载 50-100MB 的遥测数据（速度/油门/刹车等），模块 A 只需要圈速和轮胎信息，关掉遥测将加载时间从 30s 降到 5s。按需加载是性能优化的基本思路。

**Q: FastF1 缓存机制是什么？**
> `fastf1.Cache.enable_cache(dir)` 会在指定目录创建 `.ff1pkl` 文件和 `fastf1_http_cache.sqlite`。首次 `session.load()` 联网下载官方数据并写入缓存，后续直接从本地读取，不再联网。

**Q: `timedelta64[ns]` 为什么不能 JSON 序列化？**
> JSON 标准只支持 `str/int/float/bool/None/list/dict`。`timedelta64` 是 numpy/pandas 的自定义类型，`json.dumps()` 不认识它。必须先 `.total_seconds()` 转成 `float`，或用自定义 `JSONEncoder`。

## 5. Conda 虚拟环境管理

### 概念
Conda 是 Python 的包和环境管理器，创建隔离的虚拟环境，避免不同项目的依赖冲突。

```bash
conda create -n f1_project python=3.11 -y    # 创建环境
conda activate f1_project                      # 激活
conda env list                                 # 查看所有环境
conda install fastapi uvicorn                  # 安装包
pip install fastf1                             # conda 没有的用 pip
```

### 本项目环境
```
环境名: f1_project
Python: 3.11
路径: E:\anaconda3\envs\f1_project
已装: fastapi, uvicorn, requests, fastf1, pandas, numpy, matplotlib, streamlit
```

### 面试问答
**Q: Conda vs venv vs pipenv？**
> - Conda：管理 Python 版本 + 包（含非 Python 依赖如 C 库），适合数据科学（numpy/pandas 有编译依赖）
> - venv：Python 内置，只管包不管 Python 版本，轻量
> - pipenv：pip + venv 的封装，有 Pipfile 锁定依赖
> 本项目用 Conda 因为 fastf1/numpy 有 C 扩展依赖，Conda 预编译二进制安装更稳。

**Q: `pip install` 和 `conda install` 能混用吗？**
> 能，但有风险。conda 装的包和 pip 装的包可能冲突。规则：优先 conda install，conda 仓库没有的再用 pip install。不要反过来用 conda 覆盖 pip 装的包。

## 6. Git 版本控制基础

### 概念
Git 是分布式版本控制系统，记录文件变化历史，支持分支协作。

```bash
git init                          # 初始化仓库
git add .                         # 暂存所有修改
git commit -m "feat: 完成模块A"    # 提交
git push origin main              # 推送到远程
git branch feature/ml             # 创建分支
git checkout feature/ml           # 切换分支
git merge feature/ml              # 合并分支
```

### .gitignore 关键配置
```gitignore
# Python
__pycache__/
*.pyc

# 缓存数据（不提交，体积大且可重建）
cache/ergast_cache/
cache/fastf1_cache/
cache/fastf1_result_cache/

# Node.js
node_modules/

# IDE
.idea/
.vscode/

# 环境变量
.env
```

### 面试问答
**Q: `git add` 和 `git commit` 的区别？**
> `git add` 把工作区修改放入暂存区（staging area），`git commit` 把暂存区快照写入版本历史。两步设计让你能精确控制每次提交包含哪些文件。

**Q: 为什么要 .gitignore？**
> 避免把不该提交的文件加入版本库：缓存数据（体积大、可重建）、密钥（安全风险）、编译产物（平台相关）、IDE 配置（个人偏好）。本项目缓存目录有 3GB+，绝对不能提交。

**Q: `git merge` 和 `git rebase` 区别？**
> merge 保留两条分支历史，生成合并 commit；rebase 把当前分支的 commit 逐个"搬"到目标分支末尾，历史变成直线。rebase 历史更干净但会改写 commit hash，已推送的分支不要 rebase。

## 7. Pydantic 数据校验

### 概念
Pydantic 是 Python 数据校验库，FastAPI 用它自动校验请求参数和序列化响应。

```python
from pydantic import BaseModel

class UserCreate(BaseModel):
    username: str
    email: str
    age: int = 18            # 有默认值 → 可选

# FastAPI 自动校验请求体
@app.post("/users")
def create_user(user: UserCreate):
    return user              # 自动序列化为 JSON
```

### 本项目现状
> 当前模块 A 的接口直接返回 `dict`，未使用 Pydantic 模型。`schemas.py` 已创建占位文件，后续模块 B/C 补充。

### 面试问答
**Q: Pydantic v1 和 v2 的区别？**
> v2 用 Rust 重写了核心（pydantic-core），校验速度提升 5-50 倍。API 有 breaking changes：`.dict()` → `.model_dump()`，`Config` 类 → `model_config`。FastAPI 0.100+ 支持 v2。

**Q: 为什么 FastAPI 能自动生成文档？**
> FastAPI 读取路由函数的类型注解（路径参数、查询参数、Pydantic 模型），自动生成 OpenAPI 3.0 schema，渲染为 `/docs`（Swagger UI）和 `/redoc`（ReDoc）。不需要手写文档。

## 8. 项目踩坑实录

### 踩坑 1：Ergast 原域名停用
**现象**：请求 `ergast.com` 超时/拒绝连接。
**根因**：Ergast 官方已停止维护，API 不可用。
**修复**：切换到社区镜像 `https://api.jolpi.ca/ergast/f1`，接口路径完全兼容。

### 踩坑 2：FastF1 `message` 参数报错
**现象**：`TypeError: Session.load() got an unexpected keyword argument 'message'`
**根因**：参数名是 `messages`（复数），部分教程写成单数。
**修复**：`session.load(laps=True, telemetry=False, weather=False, messages=False)`

### 踩坑 3：Conda 环境路径在 PyCharm 中不生效
**现象**：PyCharm 运行报 `ModuleNotFoundError: No module named 'fastf1'`
**根因**：PyCharm 默认用系统 Python，没指向 conda 环境。
**修复**：Settings → Project → Python Interpreter → 选择 `E:\anaconda3\envs\f1_project\python.exe`。

### 踩坑 4：后端路由拼写错误导致 404
**现象**：`/api/current/driverstandings` 返回 404。
**根因**：后端路由写成 `/api/current/diverstandings`（少一个 r）。
**修复**：拼写对齐。**教训**：路由 URL、函数名、缓存键、前端调用，四处拼写必须一致。
