## 一、FastF1 库核心概念

### 1.1 什么是 FastF1

FastF1 是一个 Python 第三方库，专门用于获取和分析 F1（Formula 1）赛车数据。它封装了官方 F1 Live Timing API 的数据接口，让你能通过简单的 Python 代码获取圈速、遥测、天气等信息。

```bash
# 安装 FastF1
pip install fastf1

# 同时需要安装依赖（通常 pip 会自动安装）
pip install pandas numpy requests
```

### 1.2 fastf1.get_session() 的参数和工作原理

`fastf1.get_session()` 是 FastF1 的入口函数，用于创建一个"会话对象"（Session）。它本身不会下载任何数据，只是创建一个空壳对象，真正加载数据要调用 `session.load()`。

```python
import fastf1

# 参数一：年份（int），如 2024
# 参数二：分站轮次（int），1 = 第一站（通常是巴林）
# 参数三：会话类型（str），可选值如下：
#   "R"    = 正赛（Race）
#   "Q"    = 排位赛（Qualifying）
#   "FP1"  = 第一次练习赛（Free Practice 1）
#   "FP2"  = 第二次练习赛
#   "FP3"  = 第三次练习赛
#   "S"    = 冲刺赛（Sprint）
#   "SQ"   = 冲刺赛排位（Sprint Qualifying）

session = fastf1.get_session(2024, 5, "R")  # 2024年第5站正赛

# get_session() 只创建对象，不下载任何数据
# 此时的 session 对象内部 laps / car_data 等属性都是空的
print(type(session))  # <class 'fastf1.core.Session'>
```

**工作原理流程：**

```
get_session(year, round, session_type)
       │
       ▼
  创建 Session 对象（空壳，没有数据）
       │
       ▼
  调用 session.load(...)
       │
       ▼
  检查本地 .ff1pkl 缓存 ──命中──→ 从缓存读取
       │                         ▲
       未命中                      │
       │                         │
       ▼                         │
  请求 F1 Live Timing API ──成功─┘
       │
       ▼
  解析响应 → 填充 session.laps / session.car_data 等属性
       │
       ▼
  写入 .ff1pkl 缓存（下次直接读缓存，不再请求网络）
```

### 1.3 session.load() 参数详解

`session.load()` 是真正下载数据的方法，有四个布尔参数控制加载哪些数据：

```python
import fastf1

# 启用缓存（重要！不启用的话每次都要重新下载）
fastf1.Cache.enable_cache("./cache/fastf1_cache")

session = fastf1.get_session(2024, 5, "R")

# 四个参数的含义：
session.load(
    laps=True,        # 加载圈速表（LapTime、Sector时间、轮胎、Stint等）
    telemetry=False,  # 加载逐帧遥测数据（Speed/Throttle/Brake/RPM等，数据量大）
    weather=False,    # 加载天气数据（气温、赛道温度、风速等）
    messages=False    # 加载赛事控制消息（红旗、黄旗、罚时等文本消息）
)

# 注意：messages 是复数！写成 message 会报错：
# TypeError: Session.load() got an unexpected keyword argument 'message'
```

**参数选择策略：**

| 参数 | 数据量 | 加载时间 | 何时设为 True |
|------|--------|----------|---------------|
| `laps` | ~50KB | ~1秒 | 几乎总是需要（圈速排行、分段最快、圈速分布都依赖它） |
| `telemetry` | ~20MB | ~5-10秒 | 只在需要遥测对比（B2）时开启 |
| `weather` | ~5KB | ~1秒 | 需要天气数据时 |
| `messages` | ~10KB | ~1秒 | 需要赛事控制消息时 |

### 1.4 .ff1pkl 缓存机制

FastF1 自带的缓存机制，将 F1 官方 API 的 HTTP 响应序列化为 pickle 文件（`.ff1pkl`），下次加载同一站数据时直接从本地读取，跳过网络请求。

```python
import fastf1
import os

# 缓存目录路径
cache_dir = os.path.join(os.path.dirname(__file__), "../cache/fastf1_cache")
os.makedirs(cache_dir, exist_ok=True)  # 确保目录存在

# 启用缓存，传入目录路径
# 启用后，FastF1 会自动在这个目录下生成 .ff1pkl 文件
fastf1.Cache.enable_cache(cache_dir)

# 设置日志级别，避免控制台刷屏
fastf1.set_log_level("Warning")
# 可选级别：DEBUG / INFO / WARNING / ERROR / CRITICAL
```

**缓存文件命名规则：**

FastF1 内部根据 API URL 生成缓存文件名，形如：
```
cache/fastf1_cache/2024_05_R_laps.ff1pkl
cache/fastf1_cache/2024_05_R_telemetry.ff1pkl
cache/fastf1_cache/2024_05_R_weather.ff1pkl
```

**缓存命中验证：**

```python
# 第一次加载（无缓存，需联网下载）
session1 = fastf1.get_session(2024, 5, "R")
session1.load(laps=True, telemetry=False)
# 控制台会显示 "Requesting URL: ..." 表示正在下载

# 第二次加载（有缓存，直接读取）
session2 = fastf1.get_session(2024, 5, "R")
session2.load(laps=True, telemetry=False)
# 控制台不会显示 "Requesting URL"，因为从缓存读取了
```

### 1.7 pick_fastest() 方法

`pick_fastest()` 是 FastF1 提供的便捷方法，用于从多个圈中选出最快圈。

```python
import fastf1

fastf1.Cache.enable_cache("./cache")
session = fastf1.get_session(2024, 5, "R")
session.load(laps=True, telemetry=True)

# 方法一：对一个车手的所有圈调用 pick_fastest()
ver_laps = session.laps[session.laps["Driver"] == "VER"]
fastest_lap = ver_laps.pick_fastest()  # 返回一个 Lap 对象（DataFrame 的一行）

print(f"最快圈速: {fastest_lap['LapTime']}")         # timedelta
print(f"圈序号: {fastest_lap['LapNumber']}")          # int
print(f"轮胎: {fastest_lap['Compound']}")             # str
print(f"分段1: {fastest_lap['Sector1Time']}")         # timedelta
print(f"分段2: {fastest_lap['Sector2Time']}")
print(f"分段3: {fastest_lap['Sector3Time']}")

# 方法二：对整个 session.laps 调用 pick_fastest()（全场最快圈）
overall_fastest = session.laps.pick_fastest()
print(f"全场最快: {overall_fastest['Driver']} - {overall_fastest['LapTime']}")

# pick_fastest() 内部原理：
# 1. 过滤掉 LapTime 为 NaT 的行
# 2. 过滤掉 Deleted=True 的行
# 3. 按 LapTime 升序排序，取第一行
```

**手动实现 pick_fastest() 的逻辑：**

```python
import pandas as pd

# 手动实现等价逻辑
def manual_pick_fastest(laps_df):
    """手动找出最快圈，与 pick_fastest() 等价"""
    # 第1步：过滤无效圈速
    valid = laps_df.dropna(subset=["LapTime"]).copy()
    # 第2步：过滤被删除的圈
    if "Deleted" in valid.columns:
        valid = valid[~valid["Deleted"]]
    # 第3步：按 LapTime 排序取最快
    if valid.empty:
        return None
    return valid.sort_values("LapTime").iloc[0]

# 使用
ver_laps = session.laps[session.laps["Driver"] == "VER"]
fastest = manual_pick_fastest(ver_laps)
print(f"最快圈: {fastest['LapTime']}")
```

## 二、B1 赛道分段最快（Sector Fastest）

### 2.1 业务逻辑

F1 赛道被分成三个 Sector（分段），每个分段的时间独立计时。B1 模块的功能是：

1. **找出每个 Sector（S1/S2/S3）各自的最快车手** —— 可能三个分段分别属于不同车手
2. **找出三段总和最快的车手** —— 全场紫色标注的车手（整个赛段布局最快）
3. **每个分段的车手排行榜** —— 前端用 el-table 展示

**业务场景：** 车手在不同分段可能有不同优势。例如直道强的车手在 S1（含长直道）快，弯道技术好的车手在 S2（多弯）快。

### 2.2 后端代码逐行解析：fetch_fastf1_sector_fastest()

**代码位置：** `backend/data_source.py` 第 503-613 行

```python
def fetch_fastf1_sector_fastest(year: int, round_num: int, session_type: str = "R"):
    """
    B1：赛道各分段（Sector 1/2/3）最快车手及时间。

    参数：
        year: 赛季年份，如 2024
        round_num: 分站轮次，如 5
        session_type: 会话类型，默认 "R"（正赛）

    返回结构：
        {
          "code": 200,
          "year": 2024, "round": 5, "session": "R",
          "sectors": [
            {
              "sector": 1,
              "fastest_driver": "VER",
              "fastest_time": 26.123,           # 秒
              "fastest_time_str": "26.123",      # 格式化字符串
              "ranking": [
                {"driver": "VER", "time": 26.123, "time_str": "26.123"},
                {"driver": "NOR", "time": 26.456, "time_str": "26.456"}
              ]
            },
            // ... Sector 2, Sector 3
          ],
          "overall_fastest_driver": "VER"  // 三段总和最快
        }
    """
```

**逐段解析：**

```python
    # ===== 第1步：检查结果缓存 =====
    # 缓存键格式: sector_2024_5_R
    cache_key = f"sector_{year}_{round_num}_{session_type}"
    cached = _load_fastf1_result(cache_key)
    if cached is not None:
        # 命中缓存，直接返回之前处理好的结果，跳过 session.load()
        return cached

    # ===== 第2步：加载圈速数据 =====
    # fetch_fastf1_sessions() 内部调用 session.load(laps=True, telemetry=False)
    # 因为分段时间属于 laps 表，不需要遥测数据
    laps_df = fetch_fastf1_sessions(year, round_num, session_type)
    if laps_df is None:
        return {"code": 500, "msg": f"暂无 {year} 第{round_num}站 {session_type} 圈速数据"}

    # ===== 第3步：检查 Sector 列是否存在 =====
    # 列名是 Sector1Time / Sector2Time / Sector3Time
    # 不是 Sector1 / Sector2 / Sector3（踩坑点！）
    sector_cols = ["Sector1Time", "Sector2Time", "Sector3Time"]
    missing = [c for c in sector_cols if c not in laps_df.columns]
    if missing:
        return {"code": 500, "msg": f"圈速表缺少分段列：{missing}"}

    # ===== 第4步：遍历每个 Sector，找最快车手 =====
    sectors_data = []
    overall_fastest_driver = None
    overall_fastest_sum = float("inf")  # 用于找三段总和最快

    # enumerate(["Sector1Time", "Sector2Time", "Sector3Time"], start=1)
    # i=1, col="Sector1Time"
    # i=2, col="Sector2Time"
    # i=3, col="Sector3Time"
    for i, col in enumerate(sector_cols, start=1):

        # --- 4a. 取出 Driver 和该 Sector 时间，过滤 NaT ---
        # 某些车手某些圈可能没有 Sector 时间（进站圈、出场圈、退赛圈）
        # dropna(subset=[col]) 会删掉该列为 NaT 的行
        df = laps_df[["Driver", col]].dropna(subset=[col]).copy()
        if df.empty:
            # 这个 Sector 所有人都没有数据（极少见）
            sectors_data.append({
                "sector": i,
                "fastest_driver": None,
                "fastest_time": None,
                "fastest_time_str": None,
                "ranking": [],
            })
            continue

        # --- 4b. timedelta 转秒 ---
        # Sector1Time 等列是 timedelta64[ns] 类型
        # 不能直接 json.dump，必须转成 float
        df["seconds"] = df[col].apply(_timedelta_to_seconds)
        df = df.dropna(subset=["seconds"])  # 转换失败的可能产生 NaN

        # --- 4c. 每人取最快 ---
        # 一个车手可能跑了50圈，每圈都有一个 S1 时间
        # groupby("Driver") 按 Driver 分组
        # idxmin() 返回每组 seconds 最小值的行索引
        # 这样每个车手只保留一个最快 S1 时间
        idx = df.groupby("Driver")["seconds"].idxmin()
        per_driver = df.loc[idx, ["Driver", "seconds"]].copy()

        # 按时间升序排列（快的在前）
        per_driver = per_driver.sort_values("seconds", ascending=True).reset_index(drop=True)

        # --- 4d. 取第一名 ---
        fastest_row = per_driver.iloc[0]
        fastest_driver = str(fastest_row["Driver"])
        fastest_time = round(float(fastest_row["seconds"]), 3)

        # --- 4e. 构建排行榜 ---
        ranking = []
        for _, row in per_driver.iterrows():
            t = round(float(row["seconds"]), 3)
            ranking.append({
                "driver": str(row["Driver"]),
                "time": t,
                "time_str": _format_laptime(row["seconds"]),
                # _format_laptime() 把秒转成 "M:SS.mmm" 格式
                # 例如 86.123 -> "1:26.123"
            })

        sectors_data.append({
            "sector": i,
            "fastest_driver": fastest_driver,
            "fastest_time": fastest_time,
            "fastest_time_str": _format_laptime(fastest_row["seconds"]),
            "ranking": ranking,
        })

    # ===== 第5步：找全场三段总和最快车手 =====
    # 这个车手在赛道地图上会显示为"紫色标注"（整个赛道最快）
    # 思路：把每个车手每圈的 S1+S2+S3 加起来，找最小的
    df_all = laps_df[["Driver"] + sector_cols].copy()

    # 为每个 Sector 列创建对应的秒数列
    for col in sector_cols:
        df_all[col + "_s"] = df_all[col].apply(_timedelta_to_seconds)
    # 现在多了三列: Sector1Time_s, Sector2Time_s, Sector3Time_s

    # 三列相加得到 total
    df_all["total"] = df_all[[c + "_s" for c in sector_cols]].sum(axis=1)
    # sum(axis=1) 表示按行求和（把同一行的三列加起来）

    # 删掉 total 为 NaN 的行（某个 Sector 没有数据的圈）
    df_all = df_all.dropna(subset=["total"])

    if not df_all.empty:
        # idxmin() 返回 total 最小值的行索引
        best_row = df_all.loc[df_all["total"].idxmin()]
        overall_fastest_driver = str(best_row["Driver"])

    # ===== 第6步：组装返回 + 写缓存 =====
    result = {
        "code": 200,
        "year": year,
        "round": round_num,
        "session": session_type,
        "sectors": sectors_data,
        "overall_fastest_driver": overall_fastest_driver,
    }
    _save_fastf1_result(cache_key, result)
    return result
```

### 2.6 踩坑实录

#### 踩坑 1：Sector 列名是 Sector1Time 不是 Sector1

```python
# ❌ 错误写法
df["Sector1"]      # KeyError: 'Sector1'
df["Sector2"]
df["Sector3"]

# ✅ 正确写法
df["Sector1Time"]  # 列名带 Time 后缀
df["Sector2Time"]
df["Sector3Time"]
```

**原因：** FastF1 的列命名规范是"指标名 + Time"，表示这是一个时间类型的列。类似的还有 `LapTime`、`PitInTime`、`PitOutTime` 等。

#### 踩坑 2：timedelta 必须转换

```python
# ❌ 直接 JSON 序列化会失败
import json
result = {"time": laps_df["Sector1Time"].iloc[0]}
json.dumps(result)  # TypeError: Object of type Timedelta is not JSON serializable

# ✅ 先转成 float 秒数
from data_source import _timedelta_to_seconds
result = {"time": _timedelta_to_seconds(laps_df["Sector1Time"].iloc[0])}
json.dumps(result)  # '{"time": 26.123}'  ✅
```

**原因：** FastF1 的所有时间类型都是 `pandas.Timedelta`（内部是 `timedelta64[ns]`），Python 的 `json` 模块无法序列化这个类型。

#### 踩坑 3：NaT 处理（进站圈无分段数据）

```python
# 进站圈的 Sector 时间可能是 NaT（Not a Time）
# 如果不处理，后续计算会报错或得到 NaN

# ❌ 不处理 NaT
df["seconds"] = df["Sector1Time"].apply(lambda x: x.total_seconds())
# NaT.total_seconds() 返回 NaN，后续 groupby/idxmin 行为异常

# ✅ 先 dropna 过滤掉 NaT 行
df = df[["Driver", "Sector1Time"]].dropna(subset=["Sector1Time"]).copy()
# 再转换
df["seconds"] = df["Sector1Time"].apply(_timedelta_to_seconds)
# 再过滤一次转换后的 NaN（防御性编程）
df = df.dropna(subset=["seconds"])
```

**NaT 产生的原因：**
- 进站圈：车手从维修区出来，没有完整跑完一个 Sector
- 出场圈：车手从车库出发，第一段不完整
- 退赛圈：车手中途退赛，没有跑完全圈
- 数据缺失：官方计时系统偶发的数据丢失

## 三、B2 车手遥测对比（Telemetry Compare）

### 3.1 业务逻辑

B2 模块实现多车手多通道逐帧遥测数据对比：

1. **选择 1-3 个车手**（如 VER vs NOR vs HAM）
2. **选择对比通道**（速度/油门/刹车/RPM/挡位/DRS）
3. **后端提取每人最快圈的逐帧遥测数据**
4. **用 Distance 列做 X 轴对齐**，保证不同车手在同一距离点对比
5. **前端为每个通道画一个折线图**，多车手数据叠加显示

**业务场景：** 分析不同车手在同一个弯道/直道的刹车点差异、油门开度差异、速度差异。

### 3.2 后端代码逐行解析：fetch_fastf1_telemetry_compare()

```python
def fetch_fastf1_telemetry_compare(
    year: int,
    round_num: int,
    driver_codes: list,
    channels: list
):
    """
    B2：多车手多通道遥测数据对比。

    参数：
        year: 赛季年份
        round_num: 分站轮次
        driver_codes: 车手代码列表，如 ["VER", "NOR"]，最多 3 个
        channels: 通道列表，如 ["speed", "throttle", "brake"]

    返回结构：
        {
          "code": 200,
          "year": 2024, "round": 5,
          "channels": ["speed", "throttle"],
          "distances": [0.0, 12.5, 25.0, ...],  # 距离数组（米），用于 X 轴
          "drivers": {
            "VER": {
              "speed": [310, 305, ...],         # 速度数组
              "throttle": [100, 95, ...],       # 油门数组
            },
            "NOR": {
              "speed": [308, 303, ...],
              "throttle": [98, 92, ...],
            }
          }
        }
    """
```

**逐段解析：**

```python
    # ===== 第1步：检查结果缓存 =====
    # 缓存键包含车手和通道，确保不同组合各自缓存
    cache_key = f"telemetry_{year}_{round_num}_{'_'.join(driver_codes)}_{'_'.join(channels)}"
    cached = _load_fastf1_result(cache_key)
    if cached is not None:
        return cached

    # ===== 第2步：加载会话数据（telemetry=True 是关键！）=====
    try:
        session = fastf1.get_session(year, round_num, "R")
        # 必须设置 telemetry=True，否则 get_car_data() 会返回空
        session.load(laps=True, telemetry=True, weather=False, messages=False)
    except Exception as e:
        return {"code": 500, "msg": f"FastF1 加载失败: {e}"}

    laps = getattr(session, "laps", None)
    if laps is None or len(laps) == 0:
        return {"code": 500, "msg": "无圈速数据"}

    # ===== 第3步：通道映射表 =====
    # 前端传的是小写短名（speed/throttle 等）
    # FastF1 car_data 表的列名是首字母大写（Speed/Throttle 等）
    # 需要做映射
    channel_map = {
        "speed": "Speed",       # 速度 (km/h)
        "throttle": "Throttle", # 油门开度 (0-100)
        "brake": "Brake",       # 刹车 (True/False)
        "rpm": "RPM",           # 发动机转速
        "gear": "nGear",        # 挡位 —— 注意是 nGear 不是 Gear！
        "drs": "DRS",           # DRS 状态码
    }

    # ===== 第4步：遍历每个车手，提取遥测数据 =====
    drivers_data = {}
    all_distances = None  # 用第一个车手的距离数组作为 X 轴基准

    for code in driver_codes:
        try:
            # --- 4a. 找到该车手的所有圈 ---
            drv_laps = laps[laps["Driver"] == code]
            if drv_laps.empty:
                # 车手不存在或没跑
                continue

            # --- 4b. 取最快圈 ---
            # pick_fastest() 返回 Lap 对象
            fastest = drv_laps.pick_fastest()

            # --- 4c. 获取逐帧遥测数据 ---
            # get_car_data() 返回一个 DataFrame
            # 每行是一个时间点的赛车状态
            car_data = fastest.get_car_data()
            if car_data is None or len(car_data) == 0:
                continue

            # --- 4d. 降采样 ---
            # 原始数据约 20Hz 采样率，一圈可能有 500-1000 个点
            # 传输到前端太大了（~20MB），需要降采样到 ~200 个点
            # step = max(1, len // 200)
            # 例如 len=600, step=3，取每3个点中的第一个
            step = max(1, len(car_data) // 200)
            # iloc[::step] 表示从头到尾每隔 step 个取一个
            sampled = car_data.iloc[::step].reset_index(drop=True)
            # reset_index(drop=True) 重置索引，避免后续 .loc 出问题

            # --- 4e. 提取距离作为 X 轴 ---
            # Distance 列表示从赛道起点开始的距离（米）
            # 用于多车手数据在同一距离点对齐
            if "Distance" in sampled.columns:
                distances = sampled["Distance"].tolist()
            else:
                # 极少见情况：没有 Distance 列，用序号代替
                distances = list(range(len(sampled)))

            # 用第一个车手的距离作为 X 轴基准
            if all_distances is None:
                all_distances = [round(float(d), 1) for d in distances]

            # --- 4f. 提取各通道数据 ---
            drv_channels = {}
            for ch in channels:
                # ch 是前端传的小写短名，如 "speed"
                # channel_map[ch] 转成 FastF1 列名，如 "Speed"
                col_name = channel_map.get(ch, ch)

                if col_name in sampled.columns:
                    # 提取这一列的所有值
                    vals = sampled[col_name].tolist()
                    # 转成 float，NaN 替换为 0
                    drv_channels[ch] = [
                        round(float(v), 2) if v is not None and not pd.isna(v) else 0
                        for v in vals
                    ]
                else:
                    # 通道不存在，返回空数组
                    drv_channels[ch] = []

            drivers_data[code] = drv_channels

        except Exception as e:
            # 某个车手提取失败不影响其他车手
            print(f"[遥测提取失败] {code}: {e}")
            continue

    # ===== 第5步：组装返回 + 写缓存 =====
    if not drivers_data:
        return {"code": 500, "msg": "未能提取任何车手的遥测数据"}

    result = {
        "code": 200,
        "year": year,
        "round": round_num,
        "channels": channels,
        "distances": all_distances or [],
        "drivers": drivers_data,
    }
    _save_fastf1_result(cache_key, result)
    return result
```

from fastapi import Query

# B2 路由：多车手遥测对比
@app.get("/api/fastf1/{year}/{round}/telemetry", summary="多车手遥测对比（模块 B2）")
def get_telemetry_compare(
    year: int, round: int,
    # drivers 是逗号分隔的字符串，如 "VER,NOR"
    drivers: str = Query(..., description="车手代码，逗号分隔，如 VER,NOR"),
    # channels 也是逗号分隔，默认 "speed,throttle"
    channels: str = Query("speed,throttle", description="通道，逗号分隔")
):
    """
    参数解析：
        year: 路径参数，如 2024
        round: 路径参数，如 5
        drivers: 查询参数，如 "VER,NOR,HAM" → 拆成 ["VER", "NOR", "HAM"]
        channels: 查询参数，如 "speed,throttle" → 拆成 ["speed", "throttle"]
    """
    # 把逗号分隔的字符串拆成列表
    driver_list = [d.strip().upper() for d in drivers.split(",") if d.strip()][:3]
    # [:3] 限制最多 3 个车手

    # 参数校验
    if not driver_list:
        raise HTTPException(status_code=400, detail="至少选择一个车手")
    if not channel_list:
        raise HTTPException(status_code=400, detail="至少选择一个通道")

    return fetch_fastf1_telemetry_compare(year, round, driver_list, channel_list)

#### 踩坑 1：get_car_data() 必须在 load(telemetry=True) 之后

#### 踩坑 2：原始数据约 20Hz 采样约 20MB，必须降采样

```python
# 原始数据量计算
# F1 遥测采样率约 20Hz（每秒 20 个数据点）
# 一圈约 80-90 秒
# 一圈数据点数 = 20 * 85 = 1700 个点
# 每个点 6 个通道 = 1700 * 6 = 10200 个数值
# 3 个车手 = 30600 个数值
# JSON 序列化后约 300KB - 1MB

# 但如果一次请求多个车手多个通道，且不降采样：
# 3 个车手 * 6 个通道 * 1700 个点 = 30600 个 float
# 加上距离数组 = 额外 1700 个 float
# 总计约 32300 个数值，JSON 约 200-500KB
# 虽然不是 20MB（那是原始 pickle 文件大小），但仍然偏大

# 降采样算法：取每 N 个点中第一个
step = max(1, len(car_data) // 200)  # 目标 200 个点
sampled = car_data.iloc[::step]       # 每隔 step 个取一个

# 例如 len=600, step=3
# 取索引 0, 3, 6, 9, ... 共 200 个点
# 分辨率从 20Hz 降到约 2.4Hz，对可视化足够了
```

#### 踩坑 3：不同车手采样点数可能不同

```python
# 车手 A 的最快圈 85 秒，采样率 20Hz → 1700 个点

# ECharts 绘图时用 [distance, value] 格式，自动处理
```

#### 踩坑 6：首次请求遥测 60s 超时（2026-08-12 修复）

**现象**：前端报 `AxiosError: timeout of 60000ms exceeded`，遥测对比页空白。

**根因**：FastF1 首次加载某分站要从官网下载 50-100MB 原始 `.ff1pkl` 数据，60s 不够；且全局拦截器默认 15s 超时更容易先触发。

**修复**：
1. `telemetry.js` 3 个遥测接口单独设 `timeout: 120000`（覆盖全局默认值）
2. `request.js` 拦截器按请求对象区分提示：「遥测数据量较大，加载超时。请稍后重试（第二次会走缓存，快很多）」

**教训**：「大数据量 + 首次冷加载」接口必须单独配超时，不能和普通接口共用全局超时；同时要给用户可理解的失败提示，而不是笼统的「请求超时」。

## 四、B3 圈速分布（Lap Distribution）

### 4.1 业务逻辑

B3 模块用箱线图（Box Plot）展示每位车手所有圈速的统计分布：

1. **收集每位车手所有有效圈速**
2. **计算统计量**：最小值、Q1（第一四分位数）、中位数、Q3（第三四分位数）、最大值
3. **识别异常值**：使用 IQR × 1.5 规则
4. **按中位数排序**：快的车手排在前面
5. **前端用 ECharts boxplot 系列绘制**

**业务场景：** 一场比赛车手会跑几十圈，单看最快圈不够全面。箱线图能展示车手的圈速稳定性 —— 箱体越小说明越稳定，异常值越多说明越不稳定。

### 4.2 后端代码逐行解析：fetch_fastf1_lap_distribution()

**代码位置：** `backend/data_source.py` 第 619-707 行

```python
def fetch_fastf1_lap_distribution(year: int, round_num: int, session_type: str = "R"):
    """
    B3：全部车手的圈速分布数据，用于箱线图（Box Plot）可视化。

    参数：
        year: 赛季年份
        round_num: 分站轮次
        session_type: 会话类型，默认 "R"

    返回结构：
        {
          "code": 200,
          "year": 2024, "round": 5, "session": "R",
          "distribution": [
            {
              "driver": "VER",
              "compound": "MEDIUM",          # 最常用轮胎
              "lap_times": [80.235, 80.567, ...],  # 排序后的圈速列表
              "lap_count": 56,               # 有效圈数
              "min": 80.123,                 # 最快圈
              "max": 81.456,                 # 最慢圈
              "mean": 80.567,                # 平均圈速
              "median": 80.500               # 中位数
            },
            ...
          ]
        }
    """
```

**逐段解析：**

```python
    # ===== 第1步：检查缓存 =====
    cache_key = f"lapdist_{year}_{round_num}_{session_type}"
    cached = _load_fastf1_result(cache_key)
    if cached is not None:
        return cached

    # ===== 第2步：加载圈速数据 =====
    # B3 只需要 LapTime 和 Compound，不需要遥测
    laps_df = fetch_fastf1_sessions(year, round_num, session_type)
    if laps_df is None:
        return {"code": 500, "msg": f"暂无 {year} 第{round_num}站 {session_type} 圈速数据"}

    # ===== 第3步：检查必要列 =====
    needed = ["Driver", "LapTime", "Compound"]
    missing = [c for c in needed if c not in laps_df.columns]
    if missing:
        return {"code": 500, "msg": f"圈速表缺少列：{missing}"}

    # ===== 第4步：提取并转换圈速 =====
    df = laps_df[needed].copy()
    # LapTime 是 timedelta64[ns]，转成 float 秒数
    df["LapTimeSeconds"] = df["LapTime"].apply(_timedelta_to_seconds)
    # 过滤无效圈速（NaT 转换后是 None/NaN）
    df = df.dropna(subset=["LapTimeSeconds"])

    if df.empty:
        return {"code": 500, "msg": "本场无有效圈速数据"}

    # ===== 第5步：按车手分组统计 =====
    distribution = []
    # groupby("Driver", sort=False) 保留原始顺序（不按字母排序）
    for driver, grp in df.groupby("Driver", sort=False):
        # --- 5a. 收集并排序圈速 ---
        # sorted() 返回升序列表，快的在前
        times = sorted([round(float(t), 3) for t in grp["LapTimeSeconds"]])
        if not times:
            continue

        # --- 5b. 取最常用轮胎配方 ---
        # 一个车手可能用过 2-3 种轮胎（如 SOFT → MEDIUM → HARD）
        # 取使用圈数最多的那种
        compound_counts = grp["Compound"].value_counts()
        # value_counts() 返回按频次降序排列的 Series
        # index[0] 就是出现次数最多的值
        main_compound = str(compound_counts.index[0]) if not compound_counts.empty else "UNKNOWN"

        # --- 5c. 计算统计量 ---
        n = len(times)
        # 中位数计算
        if n % 2 == 1:
            # 奇数个：取中间值
            median_val = times[n // 2]
        else:
            # 偶数个：取中间两个的平均
            median_val = round((times[n // 2 - 1] + times[n // 2]) / 2, 3)
        # 平均值
        mean_val = round(sum(times) / n, 3)

        distribution.append({
            "driver": str(driver),
            "compound": main_compound,
            "lap_times": times,          # 排序后的圈速列表（前端用于计算 Q1/Q3）
            "lap_count": n,
            "min": times[0],             # 最快圈（已排序，第一个就是最小值）
            "max": times[-1],            # 最慢圈（最后一个就是最大值）
            "mean": mean_val,
            "median": median_val,
        })

    # ===== 第6步：按中位数升序排列 =====
    # 中位数越小 = 越快 = 排在前面
    distribution.sort(key=lambda x: x["median"])

    # ===== 第7步：组装返回 + 写缓存 =====
    result = {
        "code": 200,
        "year": year,
        "round": round_num,
        "session": session_type,
        "distribution": distribution,
    }
    _save_fastf1_result(cache_key, result)
    return result
```

#### 踩坑 1：ECharts boxplot data 格式是 [min, Q1, median, Q3, max]

// ECharts 官方文档定义的顺序就是这五个值，从左到右
```

**ECharts boxplot 数据结构图示：**

```

                    │     │
                    │  ───┤  ← 中位数线
                    │     │
              Q1 ────     │
              │           │
             min ──────────┘

#### 踩坑 2：Q1/Q3 需要手动计算

```javascript
// ❌ 不能直接用 numpy.percentile（前端没有 numpy）
// 后端也没算 Q1/Q3，只返回了排序后的 lap_times 数组

// ✅ 前端用简单索引法计算
const n = times.length
const q1 = times[Math.floor(n * 0.25)]   // 第25百分位
const q3 = times[Math.floor(n * 0.75)]   // 第75百分位

// 注意：times 必须是已排序的数组！
// 后端已经 sorted() 排过序了，前端直接用
```

**为什么不用更精确的线性插值法？**

```javascript
// 更精确的 Q1 计算（线性插值法）
function percentile(sortedArr, p) {
  const n = sortedArr.length
  const pos = (n - 1) * p
  const base = Math.floor(pos)
  const rest = pos - base
  if (sortedArr[base + 1] !== undefined) {
    return sortedArr[base] + rest * (sortedArr[base + 1] - sortedArr[base])
  }
  return sortedArr[base]
}

// 但 ECharts boxplot 要的是原始值（不是插值），
// 因为箱线图的本质是展示数据分布，用实际数据点更有意义
// 所以用简单索引法更合适
```

#### 踩坑 3：圈速需排序后才能计算四分位数

## 五、三级缓存体系详解

### 5.1 缓存架构概览

本项目设计了三级缓存，从快到慢：

```
请求到达
   │
   ▼
┌─────────────────────────────────┐
│ 第三级：处理后结果 JSON 缓存      │ ← 最快（命中即返回，跳过 session.load()）
│ 有效期：7天                      │
│ 位置：cache/fastf1_result_cache/ │
│ 内容：最终返回给前端的 dict       │
└─────────────────────────────────┘
   │ 未命中
   ▼
┌─────────────────────────────────┐
│ 第二级：FastF1 .ff1pkl 缓存      │ ← 次快（跳过 HTTP 请求，但需 session.load()）
│ 有效期：永久                     │
│ 位置：cache/fastf1_cache/        │
│ 内容：官方 API 的原始 HTTP 响应  │
└─────────────────────────────────┘
   │ 未命中
   ▼
┌─────────────────────────────────┐
│ 第一级：Ergast JSON 缓存         │ ← 永久缓存（赛果不变）
│ 有效期：永久                     │
│ 位置：cache/ergast_cache/        │
│ 内容：Ergast API 的 JSON 响应    │
└─────────────────────────────────┘
   │ 未命中
   ▼
  发起 HTTP 请求 → 下载 → 解析 → 写入各级缓存
```

### 5.2 第一级：Ergast JSON 永久缓存

**适用场景：** 历史赛果数据（赛程、成绩、车手榜、车队榜）。比赛结束后赛果不会改变，可以永久缓存。

**代码位置：** `backend/data_source.py` 第 57-91 行

```python
import os
import json
import time

# 缓存目录
CACHE_FOLDER = r"C:\Users\陈词年\PycharmProjects\f1_light_app\cache\ergast_cache"
CACHE_EXPIRE_SECONDS = 999999999  # 约31年，相当于永久
os.makedirs(CACHE_FOLDER, exist_ok=True)

def _get_cache_filepath(cache_key: str):
    """根据缓存键生成文件路径"""
    return os.path.join(CACHE_FOLDER, f"{cache_key}.json")

def _is_cache_valid(file_path: str):
    """检查缓存文件是否存在且未过期"""
    if not os.path.exists(file_path):
        return False
    modify_time = os.path.getmtime(file_path)  # 文件最后修改时间
    now = time.time()
    return now - modify_time < CACHE_EXPIRE_SECONDS

def load_from_cache(cache_key: str):
    """读取缓存"""
    fp = _get_cache_filepath(cache_key)
    if _is_cache_valid(fp):
        with open(fp, "r", encoding="utf-8") as f:
            return json.load(f)
    return None

def save_to_cache(cache_key: str, data):
    """写入缓存"""
    fp = _get_cache_filepath(cache_key)
    with open(fp, "w", encoding="utf-8") as f:
        json.dump(data, f, ensure_ascii=False, indent=2)
```

### 5.4 第三级：处理后结果 JSON 7天缓存

**适用场景：** 经过 pandas 处理后的最终结果（如最快圈排行、分段最快、圈速分布等）。命中后直接返回 JSON，完全跳过 `session.load()` 和数据处理。

**代码位置：** `backend/data_source.py` 第 184-221 行

```python
# 处理后结果缓存目录
FASTF1_RESULT_CACHE_FOLDER = os.path.join(
    os.path.dirname(os.path.abspath(__file__)),
    "../cache/fastf1_result_cache"
)
os.makedirs(FASTF1_RESULT_CACHE_FOLDER, exist_ok=True)

# 7天有效期
FASTF1_RESULT_CACHE_EXPIRE_SECONDS = 7 * 24 * 3600

def _get_fastf1_result_cache_filepath(cache_key: str):
    """生成结果缓存文件路径"""
    return os.path.join(FASTF1_RESULT_CACHE_FOLDER, f"{cache_key}.json")

def _is_fastf1_result_cache_valid(file_path: str):
    """检查结果缓存是否有效"""
    if not os.path.exists(file_path):
        return False
    return (time.time() - os.path.getmtime(file_path)) < FASTF1_RESULT_CACHE_EXPIRE_SECONDS

def _load_fastf1_result(cache_key: str):
    """读取结果缓存"""
    fp = _get_fastf1_result_cache_filepath(cache_key)
    if _is_fastf1_result_cache_valid(fp):
        try:
            with open(fp, "r", encoding="utf-8") as f:
                return json.load(f)
        except (json.JSONDecodeError, OSError):
            # 缓存文件损坏，返回 None 让主流程重新处理
            return None
    return None

def _save_fastf1_result(cache_key: str, data):
    """写入结果缓存"""
    fp = _get_fastf1_result_cache_filepath(cache_key)
    try:
        with open(fp, "w", encoding="utf-8") as f:
            json.dump(data, f, ensure_ascii=False, indent=2)
    except OSError:
        # 缓存写失败不应影响主流程（如磁盘满了）
        pass
```

### 5.5 为什么 7 天而不是永久

```python
# Ergast 缓存：永久（CACHE_EXPIRE_SECONDS = 999999999）
# 因为历史赛果 100% 不变

# FastF1 .ff1pkl 缓存：永久（FastF1 不设过期）
# 因为官方计时数据不会变

# FastF1 结果缓存：7 天（FASTF1_RESULT_CACHE_EXPIRE_SECONDS = 7 * 24 * 3600）
# 为什么？

# 原因1：官方可能修正数据
#   F1 官方偶尔会在赛后几天修正计时数据（如修正圈速被误删的情况）
#   7天窗口确保能获取到修正后的数据

# 原因2：FastF1 库更新
#   FastF1 更新版本后可能改变数据结构或修正解析逻辑
#   7天后重新处理确保用的是最新逻辑

# 原因3：平衡性能与数据新鲜度
#   太短（如1小时）：缓存命中率低，每次都要 session.load()
#   太长（如永久）：无法获取官方修正数据
#   7天是合理折中
```

### 5.6 完整缓存命中流程（文字描述）

以 B1（赛道分段最快）为例，用户请求 `GET /api/fastf1/2024/5/sector-fastest` 时的完整流程：

```
1. 路由层调用 fetch_fastf1_sector_fastest(2024, 5, "R")

2. 检查第三级缓存
   cache_key = "sector_2024_5_R"
   查找文件: cache/fastf1_result_cache/sector_2024_5_R.json
   │
   ├── 文件存在且 < 7天 → 命中！直接返回 JSON，流程结束 ✅（最快）
   │
   └── 文件不存在或 > 7天 → 未命中，继续

3. 调用 fetch_fastf1_sessions(2024, 5, "R")
   │
   │  内部执行:
   │  session = fastf1.get_session(2024, 5, "R")
   │  session.load(laps=True, telemetry=False)
   │
   │  session.load() 内部检查第二级缓存:
   │  │
   │  ├── 找到 cache/fastf1_cache/2024_05_R_laps.ff1pkl
   │  │   → 读取缓存，跳过 HTTP 请求，解析数据 ✅（次快）
   │  │
   │  └── 未找到 .ff1pkl
   │      → 发起 HTTP 请求到 F1 官方 API
   │      → 下载响应数据
   │      → 写入 .ff1pkl 缓存
   │      → 解析数据

4. 数据处理（pandas 操作）
   - 提取 Sector1Time / Sector2Time / Sector3Time 列
   - groupby("Driver") 找每人最快分段
   - 计算三段总和找全场最快
   - 转换 timedelta 为 float

5. 写入第三级缓存
   _save_fastf1_result("sector_2024_5_R", result)
   → 写入 cache/fastf1_result_cache/sector_2024_5_R.json

6. 返回结果给路由层 → 返回给前端
```

### 5.7 完整缓存示例代码

```python
# 完整的三级缓存使用示例
import fastf1
import os
import json
import time
import pandas as pd

# ===== 配置 =====
ERGAST_CACHE_DIR = "./cache/ergast_cache"
FASTF1_HTTP_CACHE_DIR = "./cache/fastf1_cache"
FASTF1_RESULT_CACHE_DIR = "./cache/fastf1_result_cache"

# 创建目录
for d in [ERGAST_CACHE_DIR, FASTF1_HTTP_CACHE_DIR, FASTF1_RESULT_CACHE_DIR]:
    os.makedirs(d, exist_ok=True)

# 启用 FastF1 官方缓存（第二级）
fastf1.Cache.enable_cache(FASTF1_HTTP_CACHE_DIR)

# ===== 第三级缓存函数 =====
def load_result_cache(cache_key, expire_seconds=7*24*3600):
    """读取处理后结果缓存"""
    fp = os.path.join(FASTF1_RESULT_CACHE_DIR, f"{cache_key}.json")
    if not os.path.exists(fp):
        return None
    if time.time() - os.path.getmtime(fp) > expire_seconds:
        return None
    try:
        with open(fp, "r", encoding="utf-8") as f:
            return json.load(f)
    except (json.JSONDecodeError, OSError):
        return None

def save_result_cache(cache_key, data):
    """写入处理后结果缓存"""
    fp = os.path.join(FASTF1_RESULT_CACHE_DIR, f"{cache_key}.json")
    try:
        with open(fp, "w", encoding="utf-8") as f:
            json.dump(data, f, ensure_ascii=False, indent=2)
    except OSError:
        pass

# ===== 使用示例 =====
def get_sector_fastest_with_cache(year, round_num):
    """带三级缓存的分段最快查询"""
    # 第三级缓存
    cache_key = f"sector_{year}_{round_num}_R"
    cached = load_result_cache(cache_key)
    if cached is not None:
        print(f"[缓存命中] 第三级结果缓存: {cache_key}")
        return cached

    # 第二级缓存（FastF1 自动处理）
    print(f"[缓存未命中] 加载 FastF1 会话数据...")
    session = fastf1.get_session(year, round_num, "R")
    session.load(laps=True, telemetry=False)
    # FastF1 内部会检查 .ff1pkl 缓存

    # 数据处理
    laps = session.laps
    result = {"code": 200, "data": "处理后的数据..."}

    # 写入第三级缓存
    save_result_cache(cache_key, result)
    print(f"[缓存写入] 第三级结果缓存: {cache_key}")

    return result
```

## 七、面试问答

### Q1：FastF1 的 session.load() 有哪些参数？telemetry=True 和 False 的区别是什么？

**答：** `session.load()` 有四个布尔参数：
- `laps=True`：加载圈速表，包含 LapTime、Sector 时间、轮胎、Stint 等信息，数据量约 50KB
- `telemetry=False`：是否加载逐帧遥测数据（Speed/Throttle/Brake/RPM/nGear/DRS），数据量约 20MB
- `weather=False`：是否加载天气数据
- `messages=False`：是否加载赛事控制消息

`telemetry=True` 时数据量大幅增加（约 20MB vs 50KB），加载时间从 1 秒增加到 5-10 秒。只在需要遥测对比（B2 模块）时开启，其他模块（B1 分段最快、B3 圈速分布）只需要 `laps=True` 即可。

### Q2：为什么要把 timedelta 转换成 float 秒数？

**答：** FastF1 的所有时间类型（LapTime、Sector1Time 等）都是 `pandas.Timedelta`（内部是 `timedelta64[ns]`）。Python 的 `json` 模块无法序列化这个类型，会抛出 `TypeError: Object of type Timedelta is not JSON serializable`。

转换函数：
```python
def _timedelta_to_seconds(td):
    if td is None or pd.isna(td):
        return None  # NaT 返回 None
    return float(td.total_seconds())
```

### Q3：FastF1 的 laps 表中 Sector 列名是什么？

**答：** 列名是 `Sector1Time`、`Sector2Time`、`Sector3Time`，不是 `Sector1`、`Sector2`、`Sector3`。这是常见踩坑点，初学者经常写错列名导致 `KeyError`。

### Q4：car_data 表中挡位列名是什么？

**答：** 列名是 `nGear`（number of Gear 的缩写），不是 `Gear`。这是 FastF1 的命名规范，`n` 前缀表示"数量"。

### Q5：如何对遥测数据进行降采样？为什么需要降采样？

**答：** F1 遥测数据原始采样率约 20Hz，一圈约 80-90 秒，产生约 1700 个数据点。3 个车手 × 6 个通道 = 30600 个数值，JSON 序列化后约 300KB-1MB，传输和渲染都偏慢。

降采样算法：
```python
step = max(1, len(car_data) // 200)  # 目标 200 个点
sampled = car_data.iloc[::step]       # 每隔 step 个取一个
```

降采样后分辨率从 20Hz 降到约 2.4Hz，对可视化来说足够了（人眼分辨不出更高分辨率），但数据量减少到原来的 1/8。

### Q6：ECharts boxplot 的数据格式是什么？

**答：** ECharts boxplot 的 data 是一个二维数组，每个元素是 `[min, Q1, median, Q3, max]` 五个数。注意顺序是 min 在前、max 在后。

```javascript
// 正确格式
series: [{
  type: 'boxplot',
  data: [
    [80.1, 80.3, 80.5, 80.7, 81.2],  // 车手A
    [80.2, 80.4, 80.6, 80.8, 81.3],  // 车手B
  ]
}]
```

### Q7：如何检测和处理 ECharts 内存泄漏？

**答：** 两个关键时机必须调用 `dispose()`：

1. **重新渲染时**：先销毁旧实例再创建新实例
```javascript
const existing = echarts.getInstanceByDom(dom)
if (existing) existing.dispose()
const chart = echarts.init(dom)
```

2. **组件卸载时**：在 `onUnmounted` 中销毁
```javascript
onUnmounted(() => {
  chart?.dispose()
  window.removeEventListener('resize', onResize)
})
```

不销毁的后果：每次切换数据都创建新实例，旧实例的 Canvas 和事件监听器不会被回收，页面越来越卡。

### Q8：Vue 3 中如何用 v-for 动态创建多个 ECharts 图表？

**答：** 使用函数式 ref：

```vue
<template>
  <div v-for="ch in channels" :key="ch" :ref="el => setChartRef(el, ch)"></div>
</template>

<script setup>
const chartInstances = ref({})
const setChartRef = (el, channel) => {
  if (el) chartInstances.value[channel] = el
}
</script>
```

关键点：
1. `:ref` 绑定一个函数，函数接收 DOM 元素和 v-for 的项
2. 把 DOM 元素存到一个对象中，用 channel 作为 key
3. 渲染图表时从对象中取 DOM 元素
4. **必须等 `nextTick()` 后 DOM 才存在**

### Q9：为什么需要 nextTick()？

**答：** Vue 的响应式更新是异步的。修改 `ref` 的值后，DOM 不会立即更新，Vue 会在下一个"tick"批量更新 DOM。

```javascript
data.value = newData      // 修改数据
console.log(chartRef.value) // 可能还是 null（DOM 还没更新）
await nextTick()            // 等待 DOM 更新
console.log(chartRef.value) // 现在有值了
```

特别是在 `v-if="data"` 从 false 变 true 时，div 元素是新创建的，必须等 `nextTick()` 后才能获取到。

### Q10：三级缓存体系中，每一级的作用和有效期是什么？

**答：**

| 级别 | 内容 | 位置 | 有效期 | 命中后效果 |
|------|------|------|--------|-----------|
| 第一级 | Ergast JSON（赛果） | cache/ergast_cache/ | 永久 | 直接返回 JSON |
| 第二级 | FastF1 .ff1pkl（HTTP响应） | cache/fastf1_cache/ | 永久 | 跳过 HTTP 请求，但仍需 session.load() |
| 第三级 | 处理后结果 JSON | cache/fastf1_result_cache/ | 7天 | 直接返回 JSON，跳过 session.load() |

第三级命中时最快（直接返回），但有效期最短（7天），因为官方可能修正数据。

### Q11：为什么结果缓存是 7 天而不是永久？

**答：** 三个原因：
1. **官方可能修正数据**：F1 官方偶尔在赛后几天修正计时数据（如误删圈速的修正）
2. **FastF1 库更新**：新版本可能修正数据解析逻辑
3. **平衡性能与新鲜度**：太短缓存命中率低，太长无法获取修正数据，7天是合理折中

### Q13：箱线图中如何计算异常值？

**答：** 使用 IQR × 1.5 规则：

```javascript
const iqr = q3 - q1              // 四分位距
const lower = q1 - 1.5 * iqr     // 下界
const upper = q3 + 1.5 * iqr     // 上界

// 超出 [lower, upper] 范围的值视为异常值
const outliers = lapTimes.filter(t => t < lower || t > upper)
```

IQR × 1.5 大约覆盖正态分布的 ±2.7σ（99.3%），即约 0.7% 的数据会被标记为异常值。

### Q14：FastF1 的 pick_fastest() 内部做了什么？

**答：** `pick_fastest()` 内部执行三步：
1. 过滤掉 `LapTime` 为 `NaT` 的行（无效圈速）
2. 过滤掉 `Deleted=True` 的行（被官方删除的圈速）
3. 按 `LapTime` 升序排序，返回第一行（最快圈）

等价的手动实现：
```python
valid = laps.dropna(subset=["LapTime"])
if "Deleted" in valid.columns:
    valid = valid[~valid["Deleted"]]
return valid.sort_values("LapTime").iloc[0]
```

## 八、踩坑总览表

| 序号 | 模块 | 踩坑点 | 原因 | 解决方案 |
|------|------|--------|------|----------|
| 1 | B1 | Sector 列名写成 Sector1 | FastF1 列名规范是"指标+Time" | 用 `Sector1Time` |
| 2 | B1 | timedelta 无法 JSON 序列化 | `json.dumps` 不支持 Timedelta 类型 | `_timedelta_to_seconds()` 转 float |
| 3 | B1 | NaT 导致 groupby 异常 | 进站圈/出场圈无分段数据 | `dropna(subset=[col])` 过滤 |
| 4 | B1 | idxmin() 报错 | DataFrame 为空时调用 idxmin | 先检查 `df.empty` |
| 5 | B2 | get_car_data() 返回空 | `session.load(telemetry=False)` | 必须设 `telemetry=True` |
| 6 | B2 | 数据量太大传输慢 | 原始 20Hz 采样约 1700 点/圈 | 降采样到 200 点：`iloc[::step]` |
| 7 | B2 | 不同车手采样点数不同 | 圈速不同导致采样点数不同 | 用第一个车手的 Distance 作为 X 轴基准 |
| 8 | B2 | 列名写成 Gear | FastF1 命名规范是 nGear | 用 `nGear` |
