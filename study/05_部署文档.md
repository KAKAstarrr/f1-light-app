## 一、容器化

### 1.1 Dockerfile（后端）

```dockerfile
# backend/Dockerfile
FROM python:3.11-slim

WORKDIR /app

# 系统依赖
RUN apt-get update && apt-get install -y --no-install-recommends \
    gcc g++ libgomp1 \
    && rm -rf /var/lib/apt/lists/*

# Python 依赖
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 应用代码
COPY backend/ ./backend/
COPY cache/   ./cache/          # 预装缓存数据（可选）
COPY ml/models/ ./ml/models/    # 训练好的模型文件

# 创建非 root 用户
RUN useradd -m -u 1000 appuser && chown -R appuser:appuser /app
USER appuser

EXPOSE 8000

CMD ["uvicorn", "backend.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

### 1.2 Dockerfile（前端）

```dockerfile
# frontend/Dockerfile
FROM node:22-alpine AS build
```

### 1.3 Nginx 配置（前端）

```nginx
# frontend/nginx.conf
server {
    listen 80;
    server_name localhost;
    root /usr/share/nginx/html;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 代理到后端（开发环境用，生产由 Railway/Render 处理）
    location /api/ {
        proxy_pass http://backend:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 静态资源缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff2)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}
```

## 二、CI/CD（GitHub Actions）

### 2.1 CI 流程 — `.github/workflows/ci.yml`

```yaml
name: CI

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  lint-and-test:
    runs-on: ubuntu-latest
    services:
      postgres:
        image: postgres:15-alpine
        env:
          POSTGRES_USER: test_user
          POSTGRES_PASSWORD: test_pass
          POSTGRES_DB: f1_test
        ports:
          - 5432:5432
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5

    steps:
      - uses: actions/checkout@v4

      - name: Setup Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.11"
          cache: pip

      - name: Install dependencies
        run: |
          pip install -r requirements.txt
          pip install pytest pytest-cov black isort

      - name: Lint
        run: |
          black --check backend/
          isort --check-only backend/

      - name: Test
        env:
          DATABASE_URL: postgresql://test_user:test_pass@localhost:5432/f1_test
          JWT_SECRET: test_secret
        run: |
          pytest backend/tests/ --cov=backend --cov-report=xml -v

      - name: Upload coverage
        uses: codecov/codecov-action@v4
        with:
          file: ./coverage.xml

  frontend-build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: "22"
          cache: npm
          cache-dependency-path: frontend/package-lock.json

      - name: Install & Build
        run: |
          cd frontend
          npm ci
          npm run build
          npm run lint
```

### 2.2 部署流程 — `.github/workflows/deploy.yml`

```yaml
name: Deploy

on:
  push:
    branches: [main]
  workflow_dispatch:            # 允许手动触发

jobs:
  deploy-backend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Deploy to Railway
        uses: railwayapp/railway-deploy-action@v1
        with:
          service: f1-backend
          railway-token: ${{ secrets.RAILWAY_TOKEN }}

  deploy-frontend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Deploy to Render
        uses: renderinc/deploy-action@v1
        with:
          service-id: ${{ secrets.RENDER_SERVICE_ID }}
          api-key: ${{ secrets.RENDER_API_KEY }}
```

## 三、Railway / Render 配置

### 3.1 环境变量清单

| 变量名 | 说明 | 示例值 | 必填 |
|--------|------|--------|------|
| `DATABASE_URL` | 数据库连接串 | `postgresql://user:pass@host:5432/f1_light` | 是 |
| `JWT_SECRET` | JWT 签名密钥 | `openssl rand -hex 32`生成 | 是 |
| `CORS_ORIGINS` | 允许的跨域来源 | `https://f1-light.vercel.app` | 是 |
| `CACHE_DIR` | 缓存目录 | `/app/cache` | 否 |
| `MODEL_DIR` | 模型文件目录 | `/app/ml/models` | 否 |
| `ENVIRONMENT` | 运行环境 | `production` | 否 |
| `LOG_LEVEL` | 日志级别 | `info` | 否 |
| `RATE_LIMIT` | 全局限流 | `100/minute` | 否 |
| `F1_CACHE_EXPIRE_DAYS` | 结果缓存过期天数 | `7` | 否 |

> **现状说明（v1.1）**：开发环境已落地 `JWT_SECRET`（无默认值兜底）+ CORS 白名单（localhost:5173/5174/5175/5176）。`DATABASE_URL` 生产切换 PostgreSQL 时需同步修改 `database.py` 的连接串配置（当前硬编码 SQLite 路径）；限流 `RATE_LIMIT` 未落地。

### 3.2 Railway 部署步骤

1. GitHub 仓库连接 Railway
2. 选择 `backend/Dockerfile` 作为构建源
3. 配置环境变量（见上表）
4. Railway 自动提供 PostgreSQL 插件 → `DATABASE_URL` 自动注入
5. 首次部署后执行数据库初始化：
   ```bash
   railway run alembic upgrade head
   railway run python scripts/seed_data.py    # 初始化车手/车队元数据
   ```

### 3.3 Render 部署步骤

1. 创建 Web Service → 选择 Docker 部署
2. 配置 `render.yaml`:
   ```yaml
   services:
     - type: web
       name: f1-backend
       runtime: docker
       dockerfilePath: backend/Dockerfile
       envVars:
         - key: DATABASE_URL
           fromDatabase:
             name: f1-db
             property: connectionString
         - key: JWT_SECRET
           generateValue: true
       healthCheckPath: /
   
     - type: web
       name: f1-frontend
       runtime: static
       buildCommand: cd frontend && npm ci && npm run build
       staticPublishPath: frontend/dist
   ```

## 四、数据更新 CRON

### 4.1 Cron 任务定义

```yaml
# 部署于 Railway/Render Cron Jobs 或 GitHub Actions Scheduled

# 每日凌晨 2 点：检查是否有新分站数据
0 2 * * * python scripts/check_new_data.py

# 每站赛后 2 小时：触发 Fantasy 结算
0 */2 * * 0 python scripts/fantasy_settlement.py --round=$(python scripts/get_latest_round.py)

# 每站赛后 1 小时：更新动态定价
30 */2 * * 0 python scripts/pricing_update.py

# 每周一：清理过期缓存
0 3 * * 1 python scripts/clean_cache.py --older-than=7

# 每周日：重新训练模型（如果新数据足够）
0 5 * * 0 python ml/train.py --auto-evaluate
```

### 4.2 关键运维脚本示例

```python
# scripts/fantasy_settlement.py
"""
Fantasy 积分结算脚本
用法: python scripts/fantasy_settlement.py --round 3
"""
import sys
from backend.game_service import GameService

def main(round_num: int):
    service = GameService()
    service.settle_round(round_num)
    print(f"Round {round_num} settlement completed.")

if __name__ == "__main__":
    import argparse
    parser = argparse.ArgumentParser()
    parser.add_argument("--round", type=int, required=True)
    args = parser.parse_args()
    main(args.round)
```

```python
# scripts/pricing_update.py
"""
动态定价更新脚本
基于赛季积分 + 近 3 场趋势更新车手/车队价格
"""
from backend.game_service import GameService

def main():
    service = GameService()
    new_prices = service.calculate_dynamic_prices()
    service.save_prices(new_prices)
    print(f"Updated {len(new_prices['drivers'])} drivers and {len(new_prices['constructors'])} constructors.")

if __name__ == "__main__":
    main()
```

### 5.4 回滚策略

| 场景 | 回滚方案 |
|------|---------|
| 代码部署失败 | Railway/Render 自动回滚到上一版本 |
| 数据库迁移失败 | `alembic downgrade -1` + PG 备份恢复 |
| Fantasy 结算错误 | 手动 `alembic downgrade` + 重新执行结算脚本 |
| 模型预测异常 | 降级到基线模型（常量预测） |
| 缓存数据损坏 | 删除缓存目录，重启服务自动重建 |

## 七、简历话术提炼

### 7.1 容器化能力

### 7.3 运维能力

> "部署到 Railway/Render 云平台，利用其免费 PostgreSQL 插件 + Hobby 计划实现零成本运营，支持 Docker 一键启动本地开发环境。"
