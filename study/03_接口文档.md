## 一、通用规范

### 1.1 请求格式
- Content-Type: `application/json`
- 认证: `Authorization: Bearer <JWT_TOKEN>`（互动类接口需要）
- 日期格式: ISO 8601 (`2026-08-04`)

### 1.2 响应格式

系统存在两种响应风格，前端拦截器已兼容处理：

**风格 1 — Ergast 透传**（模块 A 数据查询接口）：
直接返回 Ergast API 原始 JSON，无 `code` 包装。

```json
{
  "MRData": {
    "xmlns": "http://ergast.com/schemas/f1-1.0",
    "series": "f1",
    "RaceTable": { "season": "2026", "Races": [...] }
  }
}
```

**风格 2 — FastF1 / 业务接口**（圈速、遥测、鉴权、Fantasy、投票、预测）：
```json
// 成功
{
  "code": 200,
  "data": { ... },
  "msg": "success"
}

// 或直接返回业务字段
{
  "id": 42,
  "season": 2026,
  "total_cost": 98.5,
  "message": "阵容保存成功"
}

// 错误（HTTP 状态码 4xx/5xx）
{
  "detail": "用户名已存在"
}
```

### 1.3 统一错误码

| HTTP 状态码 | 含义 | 说明 |
|------------|------|------|
| 200 | 成功 | 请求正常处理 |
| 400 | 请求参数错误 | 校验失败（预算超限、重复阵容等） |
| 401 | 未认证 | Token 缺失/过期/无效 |
| 403 | 无权限 | 非 Admin 访问 Admin 接口 |
| 404 | 资源不存在 | 未找到阵容/分站数据 |
| 422 | 输入校验失败 | Pydantic 校验错误（FastAPI 自动） |
| 500 | 服务器内部错误 | FastF1 数据加载失败等 |

### 1.4 限流策略（规划中，暂未实现 slowapi）

| 接口分类 | 规划限制 | 说明 |
|---------|---------|------|
| 数据查询类 | 100 req/min/IP | 赛程/结果/圈速等 |
| FastF1 遥测类 | 30 req/min/IP | 遥测数据处理成本高 |
| AI 预测类 | 10 req/min/IP | 模型推理资源消耗 |
| Fantasy 写操作 | 20 req/min/user | 阵容提交等 |

**描述**: 获取当前 F1 赛季全部赛程日历

**响应示例**:

### A4 圈速与轮胎策略（2 个 API）

#### `GET /api/fastf1/{year}/{round}/fast-lap`
**描述**: 单场车手最快圈排行（对标 GP Tempo）

**路径参数**:
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| year | int | 是 | 赛季年份 |
| round | int | 是 | 分站序号 |

**查询参数**:
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| session_type | str | 否 | 会话类型：R(正赛), Q(排位), S(冲刺赛)，默认 R |

**响应示例**:
```json
{
  "code": 200,
  "year": 2024, "round": 5, "session": "R",
  "fastest_lap_overall": {
    "Rank": 1, "Driver": "VER", "LapTimeStr": "1:20.235",
    "LapTimeSeconds": 80.235, "Sector1": "26.123", "Sector2": "28.456", "Sector3": "25.656", "Compound": "SOFT"
  },
  "fastest_lap_ranking": [
    {"Rank": 1, "Driver": "VER", "LapTimeStr": "1:20.235", "LapTimeSeconds": 80.235},
    {"Rank": 2, "Driver": "NOR", "LapTimeStr": "1:20.567", "LapTimeSeconds": 80.567}
  ]
}
```

**踩坑说明**: `LapTime` 列是 `timedelta64[ns]` 类型，需用 `_timedelta_to_seconds()` 和 `_format_laptime()` 转换后才可 JSON 序列化。

#### `GET /api/fastf1/{year}/{round}/tyre-strategy`
**描述**: 单站正赛轮胎策略（按 Stint 分组保持进站顺序）

**响应示例**:
```json
{
  "code": 200,
  "year": 2024, "round": 5,
  "tyre_strategy": [
    {
      "driver": "VER",
      "stints": [
        {"stint": 1, "compound": "MEDIUM", "start_lap": 1, "end_lap": 24, "laps": 24},
        {"stint": 2, "compound": "HARD", "start_lap": 25, "end_lap": 56, "laps": 32}
      ]
    }
  ]
}
```

**踩坑说明**: 轮胎列名是 `Compound`（不是 `TyreCompound`），必须按 `Stint` 分组不能只 groupby compound 计数。

## 三、模块 B：GP Tempo 式遥测分析（✅ 已实现，6 个 API）

### B1 赛道分段最快

#### `GET /api/fastf1/{year}/{round}/sector-fastest`
**描述**: 获取赛道各分段（Sector 1/2/3）的最快车手及时间排行

**路径参数**:
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| year | int | 是 | 赛季年份 |
| round | int | 是 | 分站序号 |

**查询参数**:
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| session_type | str | 否 | R(正赛)/Q(排位)/S(冲刺赛)，默认 R |

**请求示例**:
```
GET /api/fastf1/2025/1/sector-fastest?session_type=R
```

**响应示例**:
```json
{
  "code": 200,
  "year": 2025,
  "round": 1,
  "session": "R",
  "sectors": [
    {
      "sector": 1,
      "fastest_driver": "NOR",
      "fastest_time": 28.553,
      "fastest_time_str": "0:28.553",
      "ranking": [
        {"driver": "NOR", "time": 28.553, "time_str": "0:28.553"},
        {"driver": "VER", "time": 28.891, "time_str": "0:28.891"}
      ]
    },
    {
      "sector": 2,
      "fastest_driver": "LEC",
      "fastest_time": 17.831,
      "fastest_time_str": "0:17.831",
      "ranking": ["..."]
    },
    {
      "sector": 3,
      "fastest_driver": "NOR",
      "fastest_time": 34.890,
      "fastest_time_str": "0:34.890",
      "ranking": ["..."]
    }
  ],
  "overall_fastest_driver": "ALO"
}
```

**技术说明**:
- 使用 FastF1 laps 表的 `Sector1Time`/`Sector2Time`/`Sector3Time` 列
- 每位车手取各分段最快时间（groupby Driver + idxmin）
- `overall_fastest_driver` = 三段总和时间最短的车手
- Sector 时间是 `timedelta64[ns]`，需 `_timedelta_to_seconds()` 转换

**踩坑**: Sector 列名是 `Sector1Time`（不是 `Sector1`），且某些圈可能 NaT（进站圈），需 dropna

### B2 车手遥测对比

#### `GET /api/fastf1/{year}/{round}/telemetry`
**描述**: 多车手指定通道遥测数据对比，用于图表可视化

**路径参数**:
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| year | int | 是 | 赛季年份 |
| round | int | 是 | 分站序号 |

**查询参数**:
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| drivers | str | 是 | 车手三字母代号，逗号分隔，如 `VER,NOR`，最多 3 人 |
| channels | str | 否 | 通道，逗号分隔，默认 `speed,throttle`。可选: `speed,throttle,brake,rpm,gear,drs` |

**请求示例**:
```
GET /api/fastf1/2025/1/telemetry?drivers=VER,NOR,LEC&channels=speed,throttle,brake
```

**响应示例**:
```json
{
  "code": 200,
  "year": 2025,
  "round": 1,
  "channels": ["speed", "throttle", "brake"],
  "distances": [0.0, 12.5, 25.0, 37.5, 50.0],
  "drivers": {
    "VER": {
      "speed": [80.5, 120.3, 285.7, 310.0, 295.2],
      "throttle": [100, 100, 100, 95, 80],
      "brake": [0, 0, 0, 0, 15]
    },
    "NOR": {
      "speed": [78.0, 118.5, 280.0, 305.0, 290.0],
      "throttle": [100, 100, 98, 90, 75],
      "brake": [0, 0, 0, 5, 20]
    }
  }
}
```

**技术说明**:
- 使用 FastF1 `session.laps[idx].get_car_data()` 获取逐帧遥测
- 需 `session.load(telemetry=True)` 才能获取 car_data
- 原始数据约 20Hz 采样（~20MB），降采样到 ~200 点/通道
- 通道映射：`speed→Speed`、`gear→nGear`（注意 n 前缀）
- `Distance` 列用于 X 轴对齐多车手数据

**踩坑**: `nGear` 列名不是 `Gear`；ECharts 实例必须 `dispose()` 否则内存泄漏

### B3 圈速分布

#### `GET /api/fastf1/{year}/{round}/lap-distribution`
**描述**: 获取全部车手的圈速分布数据，用于箱线图可视化

**路径参数**:
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| year | int | 是 | 赛季年份 |
| round | int | 是 | 分站序号 |

**查询参数**:
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| session_type | str | 否 | R(正赛)/Q(排位)，默认 R |

**请求示例**:
```
GET /api/fastf1/2025/1/lap-distribution?session_type=R
```

**响应示例**:
```json
{
  "code": 200,
  "year": 2025,
  "round": 1,
  "session": "R",
  "distribution": [
    {
      "driver": "NOR",
      "compound": "INTERMEDIATE",
      "lap_times": [82.167, 83.456, 84.123, 85.789],
      "lap_count": 53,
      "min": 82.167,
      "max": 144.979,
      "mean": 91.234,
      "median": 90.795
    },
    {
      "driver": "PIA",
      "compound": "INTERMEDIATE",
      "lap_times": [83.242, 84.567, 85.890],
      "lap_count": 52,
      "min": 83.242,
      "max": 143.155,
      "mean": 92.123,
      "median": 91.334
    }
  ]
}
```

**技术说明**:
- 收集每位车手所有有效圈速（过滤 NaT）
- 按中位数升序排列（快的在前）
- `compound` 取最常用轮胎配方（value_counts 取 top 1）
- 前端使用 ECharts boxplot 系列，需计算 [min, Q1, median, Q3, max] 五数概括
- 异常值用 IQR × 1.5 规则识别，以散点图叠加

**踩坑**: ECharts boxplot data 格式必须是 `[min, Q1, median, Q3, max]`；Q1/Q3 需排序后手动取位置

**描述**: 多车手最快圈速度-距离叠加曲线，用于对比弯道速度差异

**请求示例**:

```
GET /api/fastf1/2025/1/speed-overlay?drivers=VER,NOR,LEC&session_type=R
```

**响应示例**:
```json
{
  "code": 200,
  "year": 2025,
  "round": 1,
  "session": "R",
  "distance_grid": [0, 50, 100, 150, 200, 250, 300, 350, 400, 450, 500],
  "drivers": {
    "VER": {
      "speeds": [85.2, 120.5, 285.3, 310.0, 295.1, 180.4, 220.7, 305.2, 290.0, 150.3, 85.0],
```

**技术说明**:

**踩坑**: 不同车手采样点数量不同（因圈速不同），必须统一到相同 distance grid 才能叠加

## 十、简历话术提炼

### 10.1 接口设计能力
> "设计 39 个 RESTful API 接口，覆盖基础数据查询（Ergast 透传）、FastF1 遥测分析（速度叠加/赛道地图/天气/分段/圈速分布）、JWT 鉴权、规则加权 AI 预测、Fantasy 积分系统（动态定价/芯片系统/联盟对战）、社区投票七大模块，遵循 OpenAPI 3.0 规范，FastAPI 自动生成 Swagger 交互文档。"

### 10.2 踩坑经验
> "处理 FastF1 遥测数据时，解决了 timedelta64 类型 JSON 序列化失败、不同分站字段名不一致（Compound vs TyreCompound）、轮胎策略需按 Stint 分组保持进站顺序、多车手速度叠加需 numpy.interp 统一距离网格等工程问题。Python 路径参数 `round` 遮蔽内置 `round()` 函数导致 `TypeError: 'int' object is not callable`，改用 `round_num` 解决。"

### 10.3 安全性设计
> "实现 JWT 鉴权（python-jose + bcrypt），SQLAlchemy ORM 防注入，Pydantic 输入校验，数据库唯一约束防重复投票/阵容/联盟加入。联盟邀请码使用 secrets.token_urlsafe() 生成。CORS 中间件限制前端来源。"

### 10.4 数据工程
> "设计三级缓存策略：Ergast JSON 永久缓存、FastF1 .ff1pkl 官方缓存、处理后结果 JSON 7 天 TTL 缓存。解决 .pyc 模块缓存导致代码修改不生效的问题。"

### 10.5 Fantasy 积分系统
> "实现 F1 Fantasy 积分引擎，支持完赛/排位/最快圈/位置提升/DNF/队长加倍 6 类积分规则，自动从 Ergast 比赛结果拉取数据结算。动态定价基于双赛季积分比加权，芯片系统（Limitless/Wildcard/No Negative）每赛季限用，联盟系统支持邀请码创建/加入/排行榜。"

### 10.6 遥测数据可视化
> "基于 FastF1 实现赛道 SVG 地图渲染（坐标归一化 + 分段着色 purple/green/yellow）、多车手速度叠加对比（numpy.interp 插值对齐 50m 网格）、天气数据时序展示，前端 ECharts 联动 dataZoom 交互。"
