## 1. 模板语法 ( 2A.1 )

### 概念
Vue 3 使用「基于 HTML 的模板语法」，在编译时把模板编译成渲染函数。核心指令：

| 语法 | 作用 | 示例 |
|------|------|------|
| `{{ }}` 插值 | 文本渲染 | `{{ row.raceName }}` |
| `v-bind` (`:`) | 绑定属性 | `:data="raceList"` |
| `v-on` (`@`) | 绑定事件 | `@click="viewDetail"` |
| `v-model` | 双向绑定 | `v-model="year"` |
| `v-if / v-else` | 条件渲染 | `v-if="row.status==='Finished'"` |
| `v-for` | 列表渲染 | `v-for="r in raceList"` |
| `v-loading` | 加载指令(Element) | `v-loading="loading"` |

### 本项目代码（RaceList.vue）
```html
<el-select v-model="year" @change="onYearChange">
  <el-option v-for="y in yearOptions" :key="y" :label="`${y} 赛季`" :value="y" />
</el-select>
<el-table :data="store.raceList" v-loading="loading">
  <template #default="{ row }">
    <span>{{ row.raceName }}</span>
  </template>
</el-table>
```

### 面试问答
**Q: `v-if` 和 `v-show` 区别？**
> v-if 是真正的条件渲染，false 时元素不进入 DOM；v-show 只是 `display:none`，元素始终在 DOM。频繁切换用 v-show（切换开销小），条件很少变用 v-if（初始开销小）。

**Q: `{{ }}` 会被 XSS 攻击吗？**
> 不会。双花括号插值会做 HTML 转义，把数据当纯文本渲染。需要渲染 HTML 用 `v-html`（且要确保内容可信）。

## 2. ref / reactive 响应式 ( 2A.1 )

### 概念
Vue 3 用 Proxy 实现响应式（Vue 2 用 Object.defineProperty）。

| API | 适用 | 访问方式 | 重新赋值 |
|-----|------|---------|---------|
| `ref()` | 基本类型 / 对象 / 任意 | `.value` 访问 | 可整体替换 |
| `reactive()` | 仅对象/数组 | 直接访问属性 | 不能整体替换（会丢响应式） |

> 经验法则：基本类型用 ref，对象/数组也推荐 ref（统一 `.value`，避免 reactive 解构丢响应式）。

### 本项目代码（RaceResults.vue）
```js
import { ref, reactive } from 'vue'

const year = ref(2026)        // 基本类型 → ref
const resultList = ref([])   // 数组 → ref，模板里用 resultList，JS里用 resultList.value
// 多个布尔值打包成 reactive 对象
const loading = reactive({ result: false, fastLap: false, tyre: false })
```

### 面试问答
**Q: 为什么 ref 需要 `.value`？**
> ref 把值包成 `{ value: x }` 对象，这样 Proxy 才能拦截对 `.value` 的读写（基本类型无法直接被 Proxy 代理）。模板里自动解包不需要 `.value`，JS 里必须写。

**Q: reactive 解构会丢响应式吗？怎么解决？**
> 会。`const { count } = reactive({count:0})` 后 count 不再响应。用 `toRefs()` 转成 ref 再解构，或用 `storeToRefs()` 处理 Pinia store。

## 3. computed 计算属性 ( 2A.6 )

### 概念
computed 基于**响应式依赖**缓存结果，只有依赖变化才重算。适合「派生数据」。

```js
const total = computed(() => a.value + b.value)  // 只读
const fullName = computed({
  get: () => `${first.value} ${last.value}`,
  set: (v) => { [first.value, last.value] = v.split(' ') }
})
```

### 本项目代码（Standings.vue —— 排序+筛选的派生列表）
```js
import { computed } from 'vue'
const sortedDriverList = computed(() => {
  let list = [...store.driverStandings]   // 浅拷贝避免改原数据
  const kw = filterForm.keyword.trim().toLowerCase()
  if (kw) list = list.filter(r => driverName(r.Driver).toLowerCase().includes(kw))
  if (filterForm.sortBy === 'wins_desc') list.sort((a,b) => Number(b.wins) - Number(a.wins))
  else list.sort((a,b) => Number(b.points) - Number(a.points))
  return list
})
```

### 面试问答
**Q: computed vs methods vs watch？**
> - computed：有缓存，依赖不变不重算，用于派生展示数据。
> - methods：每次渲染都执行，无缓存。
> - watch：监听变化执行副作用（异步、改别的状态），不返回值。
> 选择：能用 computed 就别用 watch。

**Q: computed 能做异步吗？**
> 不能。computed 必须同步返回。异步派生数据用 watch + ref 或 async setup + Suspense。

## 4. watch 侦听器 ( 2A.6 )

### 概念
监听响应式数据变化，执行副作用。三种形式：
```js
watch(source, (newVal, oldVal) => {}, { deep: true, immediate: true })
watch([a, b], ([na, nb]) => {})          // 监听多个
watch(() => obj.field, (n) => {})        // 监听对象某字段
```

### 本项目代码（RaceResults.vue —— 路由参数变化重新加载）
```js
import { watch } from 'vue'
import { useRoute } from 'vue-router'

const route = useRoute()
watch(
  () => [route.params.year, route.params.round],   // 监听动态路由参数
  ([y, r]) => {
    if (y) year.value = Number(y)
    if (r) round.value = Number(r)
    if (year.value && round.value) loadAll()        // 副作用：重新拉数据
  }
)
```

### 面试问答
**Q: `watch` 默认浅层还是深层？`deep:true` 的代价？**
> 默认浅层（只监听引用变化，不监听嵌套属性）。`deep:true` 递归遍历对象所有属性，性能开销大，大对象慎用。

**Q: `watch` vs `watchEffect`？**
> watch 需显式声明依赖、能拿到新旧值、可配置 immediate/lazy；watchEffect 自动收集依赖、立即执行一次、拿不到旧值。初始化副作用用 watchEffect，需要新旧值用 watch。

## 5. v-for 列表渲染 ( 2A.4 )

### 概念
```html
<li v-for="(item, index) in list" :key="item.id">{{ item.name }}</li>
```
**必须加 `:key`**，帮 Vue 复用 DOM（diff 算法靠 key 比对）。key 要稳定唯一，别用 index（顺序变化会错乱）。

### 本项目代码（赛程列表）
```html
<el-option v-for="y in yearOptions" :key="y" :label="`${y} 赛季`" :value="y" />
<el-table :data="store.raceList">  <!-- el-table 内部已实现 v-for -->
  <template #default="{ row }">{{ row.raceName }}</template>
</el-table>
```

### 面试问答
**Q: v-for 为什么必须加 key？**
> Vue diff 用 key 判断节点是否可复用。有稳定 key 时，数据顺序变化只移动 DOM 节点；无 key（或用 index）会原地替换内容，导致状态错乱、动画失效、性能下降。

**Q: v-for 和 v-if 能写同一元素吗？**
> 不建议。v-for 优先级高于 v-if（Vue2）或 v-if 高于 v-for（Vue3），每次都要先渲染再过滤，性能差。正确做法：先用 computed 过滤，再 v-for 渲染过滤后的列表。

## 6. 生命周期 onMounted ( 2A.4 )

### 概念
组合式 API 用 `onXxx` 函数注册生命周期钩子：

| 选项式 | 组合式 | 时机 |
|--------|--------|------|
| beforeCreate/created | setup() 本身 | 实例创建 |
| beforeMount | onBeforeMount | 挂载前 |
| **mounted** | **onMounted** | **DOM 挂载后（请求数据）** |
| beforeUpdate | onBeforeUpdate | 更新前 |
| updated | onUpdated | 更新后 |
| beforeUnmount | onBeforeUnmount | 卸载前（清定时器/监听） |
| unmounted | onUnmounted | 卸载后 |

### 本项目代码（页面加载自动请求）
```js
import { onMounted } from 'vue'
onMounted(loadRaces)        // RaceList：进入页面拉赛程
onMounted(async () => {     // RaceResults：先补赛程再加载结果
  if (!store.raceList.length) await store.fetchRaceList(year.value)
  if (round.value) loadAll()
})
```

### 面试问答
**Q: 在 created 还是 mounted 请求数据？**
> 都行，但推荐 mounted（onMounted）。created 阶段 DOM 还没好，如果请求极快返回去操作 DOM 会找不到节点。而且 SSR 时 created 会执行、mounted 不会，避免 SSR 阶段发请求。本项目的请求不依赖 DOM，放 mounted 更稳。

**Q: 父子组件 mounted 顺序？**
> 先子后父。子组件先 mounted，再父组件 mounted。所以父想等所有子挂载完用 `nextTick` 或在父 mounted 里操作。

## 7. axios 拦截器封装 ( 2A.9 )

### 概念
封装 axios 实例，用拦截器统一处理：请求加 token/loading、响应统一解包、错误统一提示。

```
请求 → request拦截器(加loading) → 发出 → 响应 → response拦截器(解包+错误提示) → 业务
```

### 本项目代码（request.js —— 双格式响应兼容）
```js
const service = axios.create({ baseURL: 'http://localhost:8000', timeout: 15000 })

// 响应拦截器：兼容后端两种格式
service.interceptors.response.use(
  (response) => {
    const res = response.data
    // 后端 FastF1 接口带 code 字段，code!==200 是业务错误
    if (res && typeof res.code === 'number' && res.code !== 200) {
      ElMessage.error(res.msg || '数据加载失败')
      return Promise.reject(new Error(res.msg))
    }
    // Ergast 接口无 code 字段，直接是数据本体，原样返回
    return res
  },
  (error) => {
    if (error.code === 'ECONNABORTED') ElMessage.error('请求超时')
    else if (error.response) ElMessage.error(`[${error.response.status}] ${error.response.data?.detail}`)
    else ElMessage.error('网络错误')
    return Promise.reject(error)
  }
)
export default service
```
业务调用：`const data = await request.get('/api/current-season')` → 直接拿到数据本体，无需 `.data.data`。

### 面试问答
**Q: axios 拦截器执行顺序？**
> 请求拦截器**后注册的先执行**（栈结构，靠近真实请求），响应拦截器**先注册的先执行**（队列结构）。

**Q: 如何取消请求？**
> 用 `AbortController`（axios v0.22+）。`const c = new AbortController(); axios.get(url, { signal: c.signal }); c.abort()`。常用于搜索框切词时取消上一次请求、组件卸载时取消未完成请求防内存泄漏。

## 8. Pinia 状态管理 ( 2A.8 )

### 概念
Pinia 是 Vue3 官方推荐的状态库（替代 Vuex）。特点：去掉了 mutations、TS 支持好、模块化天然。

```js
const useStore = defineStore('f1', {
  state: () => ({ count: 0 }),           // 数据
  getters: { double: (s) => s.count * 2 },// 计算（=computed）
  actions: { add() { this.count++ } }    // 方法（可异步）
})
// 组件里：const store = useStore(); store.add()
```

### 本项目代码（stores/f1.js）
```js
export const useF1Store = defineStore('f1', {
  state: () => ({
    currentSeason: 2026,
    selectedRound: null,
    raceList: [],
    driverStandings: [],
    constructorStandings: []
  }),
  getters: {
    roundCount: (s) => s.raceList.length,
    selectedRace: (s) => s.raceList.find(r => Number(r.round) === Number(s.selectedRound)) || null
  },
  actions: {
    async fetchRaceList(year) {
      const y = year ?? this.currentSeason
      const data = y === 2026 ? await getCurrentSeason() : await getSeasonByYear(y)
      this.raceList = data.Races || []   // this 指向 state
    }
  }
})
```

### 面试问答
**Q: Pinia vs Vuex？**
> Pinia 去掉了 mutation（action 里直接改 state）、TS 类型推导更好、没有嵌套模块（每个 store 平级）、体积更小（约 1KB）、支持组合式写法（setup store）。Vue3 项目首选 Pinia。

**Q: 组件里改 store 数据会丢响应式吗？**
> 不会。`store.count = 1` 是响应式的（Pinia 用 reactive 代理）。但**解构**会丢响应式，要用 `storeToRefs(store)` 把 state/getters 转成 ref 再解构。

## 9. Vue Router 路由 ( 2A.7 )

### 概念
SPA（单页应用）靠前端路由切换页面不刷新。两种模式：`createWebHistory`（history 模式，URL 无 #）/ `createWebHashHistory`（hash 模式，URL 带 #）。

### 本项目代码（router/index.js —— 懒加载 + 动态路由 + 守卫）
```js
const routes = [
  { path: '/', name: 'race-list', component: () => import('@/pages/RaceList.vue'), meta: { title: '赛程列表' } },
  { path: '/results/:year?/:round?', name: 'race-results', component: () => import('@/pages/RaceResults.vue') },
  { path: '/:pathMatch(.*)*', component: () => import('@/pages/NotFound.vue') }   // 404
]
const router = createRouter({ history: createWebHistory(), routes })
router.beforeEach((to, from, next) => {                       // 全局守卫：改标题
  document.title = to.meta.title ? `${to.meta.title} - F1` : 'F1'
  next()
})
```

### 面试问答
**Q: 路由懒加载 `() => import()` 原理？**
> 返回一个 Promise 函数，路由被访问时才动态 import 对应 chunk。Vite/Webpack 把每个懒加载路由打成独立 JS 文件，首屏只加载当前页代码，加快首屏。本项目 RaceList/Standings/RaceResults 是 3 个独立 chunk。

**Q: history 模式刷新 404 怎么解决？**
> history 模式 URL 无 #，刷新时浏览器把 `/results/2026/1` 当真实路径请求服务器，后端没有这个文件就 404。需服务器配置把所有路径 fallback 到 `index.html`（Nginx `try_files`，Vite preview 也有 SPA fallback）。

**Q: `router.push` vs `router.replace`？**
> push 加一条历史记录（可后退），replace 替换当前记录（不可后退）。本项目 RaceResults 切分站用 replace，避免后退键堆一长串历史。

## 11. 项目踩坑实录

### 踩坑 1：响应拦截器把 Ergast 响应当错误
**现象**：所有 Ergast 接口请求都走错误分支。
**根因**：拦截器写 `if (res.code !== 200)`，但 Ergast 返回的是数据本体（无 `code` 字段），`undefined !== 200` 恒为 true。
**修复**：只在 `typeof res.code === 'number'` 时才判断（FastF1 接口才带 code）。

### 踩坑 2：一个 .vue 文件写了两个 `<template>`
**现象**：编译报错 / 页面白屏。
**根因**：复制粘贴残留，SFC 只允许一个顶层 `<template>`。
**修复**：合并为一个，删掉重复块（App.vue、Standings.vue 都中过招）。

### 踩坑 3：接口路径写反 → 404
**现象**：telemetry.js 请求 404。
**根因**：写成 `/api/fastf1/fastest-lap/${year}/${round}`，后端实际是 `/api/fastf1/${year}/${round}/fast-lap`。
**修复**：参数顺序要对齐后端路由定义。

### 踩坑 4：跨域被浏览器拦截
**现象**：前端控制台报 CORS 错误，请求发不出。
**根因**：前端在 5173、后端在 8000，不同源，浏览器拦截。
**修复**：后端加 `CORSMiddleware`（allow_origins 含 5173）。

### 踩坑 5：后端路由 URL 拼写错误
**现象**：`/api/current/driverstandings` 返回 404。
**根因**：后端写成 `/api/current/diverstandings`（少一个 r）。
**修复**：拼写对齐。**教训**：路由 URL、函数名、缓存键、前端调用，四处拼写必须一致，建议统一用常量。

### 踩坑 6：Ergast 数据嵌套深，组件直接取易报错
**现象**：`data.MRData.RaceTable.Races` 取不到。
**根因**：后端 data_source 已把 `raw["MRData"]["RaceTable"]` 解包返回，前端不应再套 `MRData.RaceTable`。
**修复**：直接用 `data.Races`。**教训**：先在浏览器 Network 看真实响应结构，再写映射。

### 踩坑 7：路由空路径子路由 redirect 无限循环 → 栈溢出
**现象**：访问 `/race-center` 页面白屏，控制台 `RangeError: Maximum call stack size exceeded` + `[VUE_ROUTER_R0103]` 警告。
**根因**：
```javascript
children: [{ path: '', redirect: '/race-center?tab=overview' }]
```
`/race-center` → 空路径子路由匹配 → redirect 到 `/race-center?tab=overview` → 路径仍是 `/race-center` → 再次匹配 → **无限循环**。
**修复**：删除 children 配置，让组件自己处理默认值：`route.query.tab || 'overview'`。
**教训**：**重定向目标路径不能再匹配当前路由**。想让「无参访问显示默认 Tab」，优先在组件内用 `||` 默认值，不要用路由 redirect。

### 踩坑 8：Vue Router 4 的 `next()` 已废弃
**现象**：控制台 `[VUE_ROUTER_R0025] next() is deprecated` 警告。
**根因**：`router.beforeEach((to, from, next) => { ...; next() })` 是 Vue Router 3 写法，Router 4 改**直接返回值**。
**修复**：
```javascript
// 改前
router.beforeEach((to, from, next) => { document.title = ...; next() })
// 改后
router.beforeEach((to) => { document.title = ... })  // 不返回 = 放行
```
**对照表**：`next(false)` → `return false`；`next('/login')` → `return '/login'`；`next()` → 不写 return。

### 踩坑 9：Element Plus `el-checkbox` 的 `:label` 作 value 已废弃
**现象**：控制台 `ElementPlusError: [ElCheckbox] label as value will be deprecated in version 3.0.0`。
**根因**：Element Plus 2.6+ 把「选中值」属性从 `label` 迁移到 `value`，`label` 未来只做展示文本。
**修复**：`:label="y"` → `:value="y"`（本项目 HistoryCompare.vue 中过招）。
**教训**：组件库版本升级会产生「静默废弃」，用 `grep -rn ":label=" src` 全局排查同类写法。

### 踩坑 10：大数据量接口超时（遥测 60s 不够）
**现象**：`AxiosError: timeout of 60000ms exceeded`。
**根因**：FastF1 首次加载某分站需从官网下载 50-100MB 原始数据，60s 超时不够；且全局拦截器 15s 超时会先触发。
**修复**：
1. 遥测专用接口（telemetry.js）单独设 `timeout: 120000`，覆盖全局默认
2. 拦截器按请求配置区分提示：「遥测数据量较大，加载超时。请稍后重试（第二次会走缓存，快很多）」
**教训**：**「大数据量 + 首次冷加载」接口必须单独配超时**，不能和普通接口共用全局超时；配超时同时要给用户可理解的失败提示。

## 2B.0 全局优化知识点（2026-08-11）

### 1. Vue 3 Composables — 逻辑复用模式

**问题**：11 个页面各自硬编码 `yearOptions = [2025, 2024, 2023]`，默认 year 有的 2024 有的 2025，不统一也不包含 2026。

**方案**：抽取 `composables/useYearSelection.js`

```js
// composables/useYearSelection.js
import { ref } from 'vue'
import { useF1Store } from '@/stores/f1'
import { YEAR_OPTIONS } from '@/utils/f1-constants'

export function useYearSelection(defaultYear) {
  const store = useF1Store()
  const year = ref(defaultYear || store.currentSeason || 2026)
  const syncYearToStore = () => { store.setSeason(year.value) }
  return { yearOptions: YEAR_OPTIONS, year, syncYearToStore }
}
```

**页面使用**：
```js
const { yearOptions, year, syncYearToStore } = useYearSelection()
const onYearChange = async () => {
  syncYearToStore()
  await store.fetchRaceList(year.value)
  // ... 页面特定逻辑
}
```

**知识点**：
- Vue 3 Composition API 的 composable 模式 = React Custom Hook 的等价物
- composable 函数在 `setup()` 中调用，返回的 ref/getter 与组件生命周期绑定
- 多个组件调用同一 composable，每个组件获得独立的状态副本（不共享）
- 如果要跨组件共享状态，用 Pinia store 而非 composable

### 2. Pinia Store 缓存层 — 请求去重 + TTL 过期

**问题**：车手列表、分站列表在多个页面重复请求 API，无缓存。

**方案**：Store 内部加缓存 Map + 时间戳

```js
state() {
  return {
    _driverCache: {},      // { 2025: [...], 2024: [...] }
    _raceListCache: {},
    _fetchTime: {},        // { 'drivers_2025': timestamp }
  }
},
actions: {
  async fetchDrivers(year) {
    const cacheKey = `drivers_${year}`
    // 命中缓存（10 分钟内）
    if (this._driverCache[year]?.length &&
        Date.now() - (this._fetchTime[cacheKey] || 0) < 600000) {
      return this._driverCache[year]
    }
    // 2026 mock
    if (year === 2026) return MOCK_2026_DRIVERS
    // 请求 API
    const data = await getDriversByYear(year)
    const drivers = data?.Drivers || []
    this._driverCache[year] = drivers
    this._fetchTime[cacheKey] = Date.now()
    return drivers
  }
}
```

**知识点**：
- Pinia 的 state 可以存私有缓存数据（用 `_` 前缀标记内部使用）
- 缓存 TTL（Time To Live）模式：存数据时记录时间戳，读取时比较 `Date.now() - timestamp < TTL`
- 2026 年特殊处理：Ergast API 未覆盖 2026 赛季，前端用 mock 数据兜底
- `?.` 可选链 + `|| []` 空值合并 = 防御性编程标准模式

### 3. useNextRace Composable — 分站状态计算

**业务规则**：
| 状态 | 判定 | 用途 |
|------|------|------|
| upcoming | `date > now` 第一站 | AI 预测 / Fantasy 锁定 |
| ongoing | `\|date - now\| < 4h` | 投票锁定 |
| lastCompleted | `date < now` 最后一站 | 投票页显示上一场结果 |

```js
const upcomingRace = computed(() => {
  const now = new Date()
  return store.raceList.find(r => {
    const d = new Date(`${r.date}T${r.time || '00:00:00Z'}`)
    return d && d > now
  }) || null
})
```

**知识点**：
- `computed` 是惰性的：只有被读取时才计算，且依赖未变时返回缓存值
- `Date` 构造函数解析 ISO 8601 格式：`new Date("2025-05-04T20:00:00Z")`
- Ergast 赛程数据结构：每个 race 有 `date`（日期）和 `time`（时间，UTC）字段
- `find()` 返回第一个匹配元素或 `undefined`，用 `|| null` 统一为 null

### 4. 分站锁定模式 — 不可切换的 UI

**设计决策**：AI 预测和 Fantasy 不是「默认选」upcoming 站，而是「只能选」upcoming 站。

```html
<!-- 不可切换的锁定标签（不是 disabled 下拉框） -->
<div class="race-lock-bar" v-if="upcomingRace">
  <span class="lock-icon">🔒</span>
  <span class="race-name">{{ upcomingRace.raceName }}</span>
  <el-tag type="success" size="small">即将开始</el-tag>
</div>
<el-empty v-else description="暂无即将开始的分站" />
```

**知识点**：
- `v-if` / `v-else` 条件渲染：有数据显示锁定栏，无数据显示空状态
- 不用 disabled `el-select` 而用标签展示，因为 disabled 下拉框暗示「有选项但不可选」，而标签明确表示「就是这一站」
- year/round 从 `computed` 派生，不是用户输入：`const year = computed(() => Number(upcomingRace.value?.season))`
- AI 预测和 Fantasy 各自独立调用 `useNextRace()`，不共享状态

### 5. Axios 请求拦截器 — Authorization Header

service.interceptors.request.use((config) => {

**知识点**：

### 7. 面试问答

**Q: 为什么用 composable 而不是 mixin？**
A: Vue 3 推荐用 composable 替代 mixin。mixin 的问题：1) 数据来源不透明（隐式注入）；2) 命名冲突风险；3) 类型推断困难。composable 显式返回值，来源清晰，TypeScript 友好。

**Q: Pinia 缓存和 HTTP 缓存（Cache-Control）的区别？**
A: Pinia 缓存是应用层内存缓存，优势是精确控制（可按 year 分别缓存、可手动清除），劣势是页面刷新后丢失。HTTP 缓存是浏览器层缓存，由 Cache-Control header 控制，适合静态资源。两者互补：API 数据用 Pinia 缓存，静态资源用 HTTP 缓存。

**Q: computed 和 watch 的区别？什么时候用哪个？**
A: `computed` 用于派生状态（从已有值计算新值），是惰性的且缓存结果。`watch` 用于响应式副作用（值变化时执行异步操作或副作用）。本项目中 `upcomingRace` 用 computed（从 raceList 派生），`loadPrediction` 在 onMounted 中调用（不用 watch，避免重复触发）。

**Q: 为什么 AI 预测和 Fantasy 不共享 composable 状态？**
A: `useNextRace()` 每次调用返回独立的 computed 引用，但底层都读取同一个 `store.raceList`。两个页面各自调用 `useNextRace()` 获得各自的 `upcomingRace` computed，虽然值相同（都指向同一场比赛），但页面状态独立。这确保了一个页面的操作（如年份切换）不会影响另一个页面。

**Q: 后端 Ergast 缓存从永久改为 1 小时的原因？**
A: 永久缓存适用于历史赛果（不变的数据）。但当前赛季（如 2025/2026）赛程可能更新（新增分站、时间调整），永久缓存会导致赛季中进行时看不到新数据。1 小时 TTL 兼顾性能和实时性。
