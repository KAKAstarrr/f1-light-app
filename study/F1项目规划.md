# 轻量化 F1 数据互动 App — 项目规划书

> 定位：简历级全栈 + AI 应用项目 | 目标人群：应届毕业生 / AI 学习者
> 核心价值：**用真实数据 + 真实 AI 模型，做出有差异化的产品**

---

## 一、可行性结论：✅ 非常高

| 维度 | 评估 | 说明 |
|------|------|------|
| 数据获取成本 | ⭐⭐⭐⭐⭐ | Ergast API 完全免费、无需 key；FastF1 开源 |
| 技术门槛 | ⭐⭐⭐ | 对新手有学习曲线，但资料丰富、社区活跃 |
| AI 学习价值 | ⭐⭐⭐⭐⭐ | XGBoost 是工业界经典，特征工程能真正练手 |
| 简历差异化 | ⭐⭐⭐⭐⭐ | 大多数简历项目是"待办清单/博客"，这个有真实 ML 落地 |
| 时间投入 | 3-5 个月（业余） | 可按阶段交付，每阶段都是可展示的成果 |

**为什么这个项目比"做个博客/电商"更适合写简历：**
1. 集成了真实第三方 API（工程能力）
2. 有机器学习落地场景（AI 能力，当下最值钱）
3. 有互动型产品功能（产品思维）
4. 有数据可视化（综合能力）
5. 主题新颖不烂大街（面试官记得住）

## 二、技术栈选型（为新手优化）

```
后端      : Python 3.11 + FastAPI（轻量、自动生成 API 文档、上手快）
前端      : React + Vite + TailwindCSS（或 Vue3，看个人偏好）
数据库    : SQLite（开发）→ PostgreSQL（生产）
ML        : XGBoost + scikit-learn + pandas
数据源    : Ergast API（赛程/成绩）+ FastF1（圈速/轮胎）
部署      : Docker + Railway / Render / Vercel（免费额度够用）
版本管理  : Git + GitHub（务必规范 commit）
```

**选型理由：**
- FastAPI 比 Flask 更现代，自带 Swagger 文档，简历加分
- React + Vite 是当前主流，招聘市场认可度高
- SQLite 零配置，新手不用一上来就搞数据库运维
- XGBoost 文档完善、调参直观，是学习树模型的最佳入口

## 四、功能模块详解

### 模块 A：基础数据（低成本，2-3 周）
- **A1 当年赛程列表**：调 Ergast `/current.json`，展示分站日历
- **A2 分站基础结果**：调 Ergast `/results/{round}.json`，展示 Top10
- **A3 车手/车队信息**：调 Ergast，展示车手榜、车队榜
- **A4 单站圈速/轮胎**：用 FastF1 `get_session()`，展示最快圈、轮胎策略

> 这部分是"地基"，让产品看起来完整，但不是简历亮点。

### 模块 B：互动功能（差异化，3-4 周）
- **B1 分站最佳车手投票**：每站后用户投票选"最佳车手"，实时统计
- **B2 Fantasy 预测游戏**：
  - 赛前拖拽排列车手名次
  - 赛后按规则自动结算积分（如预测第1名正确得25分，差1位扣5分）
  - 累计排行榜、好友 PK
- **B3 赛季总排行**：积分榜、连胜榜

> 这部分体现"产品 + 互动"能力，用户粘性来源。

### 模块 C：AI 预测（核心亮点，4-6 周）⭐
- **C1 数据收集**：爬取/调用历史赛季数据（排位赛成绩、发车位、历史战绩、赛道特性）
- **C2 特征工程**：
  - 车手历史胜率、排位赛位次、该赛道历史表现
  - 车队赛季表现趋势、近3场状态
  - 天气、赛道类型（街道/永久）
- **C3 模型训练**：XGBoost 多分类（预测夺冠概率），交叉验证
- **C4 预测服务**：赛前输出每位车手夺冠概率 + Top3 预测
- **C5 模型评估**：准确率、对数损失，可视化特征重要性

> 这是你"学会用 AI"的核心载体，也是面试时最被追问的模块。

## 六、AI 预测模块深入指南（学习重点）

这是你"学 AI"的核心，建议这样学：

### 6.1 学习路径
1. **先补基础**：pandas 数据处理、matplotlib 可视化（1 周）
2. **理解树模型**：决策树 → 随机森林 → XGBoost（看《统计学习方法》决策树章节 + 官方文档）
3. **特征工程实战**：这是 ML 工程师最值钱的能力，F1 场景非常适合练
4. **模型评估**：准确率不够，要学会用对数损失、混淆矩阵、交叉验证

### 6.2 特征设计建议
```
车手维度  : 历史胜率、近5场平均完赛位次、排位赛位次、该赛道历史成绩
车队维度  : 赛季积分趋势、赛车升级节奏、可靠性（退赛率）
赛道维度  : 超车难度、赛道类型、历史杆位转化率
环境维度  : 天气预报、温度（影响轮胎）
```

### 6.3 简历话术示例
> "基于 Ergast 历史数据构建 F1 夺冠概率预测模型，使用 XGBoost 进行多分类，
> 设计 15+ 维度特征（车手状态、车队趋势、赛道特性），通过 5 折交叉验证调优，
> 模型 Top3 命中率达 XX%，并将模型封装为 REST API 服务前端实时预测。"

## 八、风险与应对

| 风险 | 应对 |
|------|------|
| F1 赛季间歇期无实时数据 | 用历史赛季数据开发和训练，赛季期上线 |
| 预测准确率不高 | 简历看重过程（特征工程、模型对比），不要求冠军预测 |
| 新手卡在某模块 | 每阶段先做 MVP，不求完美；善用 AI 辅助编程 |
| 部署成本 | 全部用免费额度（Railway/Render/Vercel） |
| 半途而废 | 每阶段都是可展示成果，即使只做到阶段2也是完整项目 |
